# AssetReplay

다중 자산군의 히스토리 데이터를 축적하고, 과거 시점의 투자 성과를 재현·비교한다.

"그때 샀더라면 지금 얼마일까"에 답하려면 **그때의 값을 그대로 갖고 있어야 한다.**
이 프로젝트는 그 데이터를 쌓는 일부터 시작한다.

---

## 현재 상태

**외환(FX)**·**가상자산**·**주식/ETF**·**예금**·**부동산** — 다섯 자산군이 모두 동작한다.
첫 화면은 시장 지표 15개와 세 나라의 주요 경제 뉴스를 보이는 **대시보드**다(014). 상단 바 오른쪽 끝의 ☾ 단추로 모든 화면을 **블랙 배경**으로 볼 수 있다(이 브라우저에 기억 — 처음은 밝게).

| 011 | 주식·가상자산·예금(+주식 설정) | 투자 방식을 고른다. **적립식**(주식·가상자산): 매일·매주·매달·매년 같은 금액을 넣어 사 모은 성과 — 휴장·시세 없는 날의 납입은 다음 거래일로 미루고, 주식은 1주가 될 때까지 매수 대기금에 모은다(배당 재투자 선택). 보드는 총 납입 원금·매매 수수료 총액·세금 총액·투자 수익·수익률, 차트에 누적 납입 원금 점선. **정기 적금**(예금 — 시중은행·상호금융): 1년 만기 12회 적금이 만기되면 정기예금과 합쳐 1년 정기예금에 넣고 새 적금을 붓는다. **주식 매도 세금 설정**: 국내 매도 세율(기본 0.20%)·해외 양도소득세율(기본 22%)·해외 연간 기본공제(기본 250만 원)를 설정에서 바꾼다. 가상자산은 과세 시행(2027-01-01) 전이라 매도 세금이 0이다 |
| 012 | 외환·주식·가상자산(+네 자산군 이력) | 외환 일자별 표의 일·주·월을 바꿔도 화면이 움직이지 않는다(먼 날짜를 고르면 그대로 표의 처음으로). 주식·가상자산 일자별 투자 성과 표에 일·주·월(일시금·적립식 — 외환과 같은 기준일 규칙, 옮겨진 기준일 📅·끝나지 않은 구간 ⏳, 배당락·재투자·납입 행은 단위와 무관하게 보이고 출처 결측은 일 단위에 결측 구간 행). 최근 시뮬레이션 이력을 브라우저 대신 **로컬 DB**에 저장(다른 브라우저에서도 같다, 보관 기간 설정 7·30·90·180·365일·무기한 — 기본 30일, 012 전 브라우저 이력은 처음 열 때 옮긴다). 주식·가상자산·예금 원금 칸이 10,000,000원으로 열린다. 주식·가상자산 성과 보드(일시금·적립식)에 **현재 잔고**(기준일의 원화 총자산 — 잔고 + 예수금, 매도 비용 전) 칸을 더했다. 해외 주식 매도 칸에 양도차익의 구성(매도금액 − 취득가(배당 재투자 매수 포함) − 수수료)을 보인다 |
| 013 | 주식·가상자산·예금·부동산(투자 비교) | 새 화면 **투자 비교**. 한 자산군의 대상 2~10개(예금은 투자처 다섯까지)를 메뉴와 같은 검색으로 더해 같은 조건(시작일·금액·투자 방식·원금 통화·배당 재투자)으로 한 번에 실행하고 나란히 본다 — 주식·가상자산 일시금·적립식, 정기예금·정기 적금, 부동산 매입 후 보유. 비교 표(투자 원금·현재 가치·비용(이미 반영된 몫·기준일 매도 가정 몫)·투자 수익·수익률 — 메뉴와 같은 값, 머리를 눌러 정렬), 수익률 추이(보유 중 선 + 기준일의 매도 후 점), 최종 지표 막대. 계산할 수 없는 대상이 하나라도 있으면 비교 전체를 막고 가장 이른 가능한 시작일을 제안한다. 받는 중인 대상은 끝나면 채우고, 조건을 바꾸면 결과를 흐린다. 이름을 붙여 저장한 비교는 로컬 DB에 지울 때까지 남고, 불러오면 지금 데이터로 다시 실행한다. 비교는 최근 시뮬레이션 이력에 남지 않는다. 비교 표에는 대상마다 시작일과 기준일의 1단위 가격과 그 등락(차이·등락률)도 보인다 — 주식은 상장국 통화의 수정주가(액면분할 반영), 가상자산은 일봉 시가, 예금은 발표 금리(%p 차이), 부동산은 그 달 시세. 줄 끝의 "투자 시뮬레이션"을 누르면 그 대상을 해당 메뉴에서 같은 조건으로 실행한 결과(투자 결과 패널·성과 추이·일자별 투자 성과)가 모달로 뜬다(최근 시뮬레이션 이력에는 남지 않는다) |
| 014 | 대시보드(지표·뉴스) | 첫 화면 **대시보드**. 오늘 날짜(한국 시간)와 지표 카드 15개(KOSPI·KOSDAQ·다우·나스닥·S&P 500·필라델피아 반도체·니케이 225·항셍·상해 종합·달러·엔(100엔)·유로·WTI·금·VIX — 현재 값·전일 대비 차이·등락률·장 상태(장중·점심 휴장·마감·휴장·개장 전 — 시장 현지 시각 기준)·기준 시각, 보이는 동안 1분마다 갱신). 카드를 누르면 대시보드 위에 **지표 모달**(주소 `/dashboard/{지표}?range=` — 새로고침·즐겨찾기도 같은 모달) — 변화 까닭(마지막 세션 이후의 시황 기사 최대 3개, 출처 글자 그대로, 누르면 새 탭), 보는 기간 여덟(처음 보이는 범위 — 일·주는 장중 시세(최근 5세션 5분·최근 1개월 30분), 월·1년·5년·10년·20년·모두는 로컬 DB에 쌓은 확정 일봉 전부를 받아 그 기간만 보이고 왼쪽으로 끌면 첫 날까지 이어서 보인다. 오늘은 잠정, 출처 결측은 선을 끊는다), 그 아래 일자별 표(시가·고가·저가·종가·대비·등락률, 일·주·월, 스크롤로 더 본다). 환율 카드는 시장 환율이고 환율 추이는 외환 메뉴와 같은 한국은행 매매기준율이다. 아래에 한국·미국·일본의 주요 경제 뉴스 10개씩(네이버 증권 주요뉴스·Yahoo Finance Latest News·Yahoo!ファイナンス ヘッドライン — 원문 제목, 누르면 새 탭, 저장하지 않고 10분 동안만 둔다). 외환 메뉴의 일자별 환율 표 오른쪽 끝에 **등락폭·등락율**(바로 아래 행 대비 — 일은 직전 고시일, 주·월은 직전 주·달의 대표값, 오르면 ▲ 빨강·내리면 ▼ 파랑. 내려받은 CSV에도 맨 끝 두 열)을 더했다 |

자산군 확장 순서는 고정되어 있다 — **외환 → 가상자산 → 주식/ETF → 예금 → 부동산.**
한 번에 하나씩, 수집부터 화면까지 동작하는 수직 슬라이스로 완결한다.

**005는 이 순서를 한 칸 건너뛰었다.** 사용자가 쓰던 Google Apps Script 시뮬레이터를
대체하는 것이 먼저 필요했기 때문이며, 사용자 승인을 받은 결정이다(`specs/005-stock-investment-simulation/plan.md`의
Complexity Tracking에 근거와 함께 기록). 006은 005의 개선이라 같은 자산군이다. **007이 건너뛴
가상자산을 채웠고, 008이 예금을, 009가 부동산을 더했다** — 순서의 다섯 자산군이 모두 구현되었다. 010은 새 자산군이 아니라
네 자산군 화면(차트·이력)의 개선이다. 011도 새 자산군이 아니라 세 자산군의 투자 방식(적립식·적금)과 주식 매도 세금 설정이다. 012도 새 자산군이 아니라 표의 단위·스크롤과 이력의 보관 위치다. 013도 새 자산군이 아니라 한 자산군 안의 대상 여럿을 같은 조건으로 나란히 보는 비교 화면이다. 014도 새 자산군이 아니라 시장 지표와 뉴스를 한눈에 보는 조회 화면이다.

부동산이 마지막인 이유는 지역·단지·면적 축의 비정기 거래 데이터라, 나머지 넷의 균일한
일별 시계열과 형태가 근본적으로 다르기 때문이다.

## 시작하기

### 준비물

| 항목 | 버전 |
|------|------|
| Python | 3.14+ |
| Node.js | 20.9+ (`next` 요구 버전) |
| MySQL | 8.0+ (InnoDB, utf8mb4) |
| 한국은행 ECOS 인증키 | [ecos.bok.or.kr](https://ecos.bok.or.kr)에서 발급 |
| 키움증권 REST API 앱 키·시크릿 | 006의 종목 검색용 목록. 아래 "데이터 출처"의 이용 조건 참조 |

### 설치

```bash
# 백엔드
cd backend
python3.14 -m venv .venv
.venv/bin/pip install -e '.[dev]'

# 프론트엔드
cd ../frontend
npm install
```

### 설정

`.env.example`을 **저장소 루트**에 `.env`로 복사하고 값을 채운다.

```bash
cp .env.example .env
```

최소한 다음 다섯 개가 필요하다.

```
ECOS_API_KEY=발급받은_인증키
DB_HOST=localhost
DB_NAME=assetreplay
DB_USER=사용자명
DB_PASSWORD=비밀번호
```

주식 종목 검색(006)을 쓰려면 키움증권 인증 정보도 넣는다. 비어 있으면 검색용 목록을 받지
않고, 검색 화면이 "인증 정보가 설정되지 않았습니다"와 할 일을 알린다(일본 종목 검색과
시뮬레이션은 그대로 동작한다).

```
KIWOOM_MODE=real
KIWOOM_APP_KEY=발급받은_앱_키
KIWOOM_APP_SECRET=발급받은_시크릿
```

가상자산(007)은 로그인·키가 필요 없다. 출처가 기본 사용자 에이전트를 403으로 막으므로 브라우저형 문자열을 쓴다 —
`INVESTING_USER_AGENT` 줄이 없으면 코드의 기본값을 쓰고, **비워 두면 차단된다**(차단 경로를 재현하는 수단이다).

부동산(009)은 **공공데이터포털 인증키**(`DATA_API_KEY`)를 쓰고, 포털에서 네 자료를 **각각 활용신청**해야 한다 — 국토교통부 아파트
매매 실거래가 **상세 자료**, 행정안전부 법정동코드, 국토교통부 공동주택 단지 목록, 공동주택 기본 정보(같은 계정이면 키는 하나다).
등록되지 않은 자료는 HTTP 403(사유 30)으로 막히고 화면이 "인증키 설정과 활용신청을 확인하세요"를 보인다. 첫 거래 달을 찾을 탐색
시작 달 `APT_TRADE_PROBE_START`(예: `2005-01`)는 **코드에 기본값이 없다** — `.env.example`에서 옮긴다(없으면 실거래 수집이 사유와 함께
멈춘다).

```
DATA_API_KEY=공공데이터포털_인증키
APT_TRADE_PROBE_START=2005-01
```

예금(008)은 환율과 **같은 ECOS 인증키**를 쓴다 — 더 넣을 것이 없다. **ECOS 인증키는 발급일부터 2년 유효하다**(ECOS 이용약관
제4조 ③). 만료되면 환율·예금 수집이 함께 인증 실패(`auth`)로 멈추므로 만료 전에 ECOS에서 연장한다.

`.env`는 gitignore된다. 나머지 항목은 기본값이 있으며 `.env.example`에 주석으로 설명한다.
**인증 정보를 고치면 백엔드를 다시 띄운다** — 기동 시에 읽고, 인증 실패 막힘도 재시작에서
풀린다.

### 스키마 적용

```bash
cd backend && .venv/bin/python -m alembic upgrade head
```

스키마는 Alembic 리비전으로만 관리한다. 수동 DDL은 쓰지 않는다.

새 기능이 테이블을 더하면 기존 설치도 같은 명령으로 올린다 — 012는 시뮬레이션 이력 테이블 둘(`simulation_history`·`history_setting`)을 더한다.
올리지 않으면 이력 칸이 "이력을 불러오지 못했습니다"를 보인다(시뮬레이션은 된다).
013은 저장한 비교 테이블 하나(`saved_comparison`)를 더한다 — 올리지 않으면 투자 비교 화면의 저장한 비교 칸이 "저장한 비교를 받지 못했습니다"를 보인다(비교 실행은 된다).

### 첫 수집

데이터가 없으면 화면이 비어 있다. 상단 바 우측의 **`⟳ 수집 현황`** 을 눌러 수집 화면으로
가서 통화를 고르고 시작한다.

수집은 서버에서 돌기 때문에 **화면을 떠나거나 브라우저를 닫아도 계속 진행된다.**
돌아오면 그동안 진행된 만큼 시간축이 채워져 있다.

> **호출 한도 주의**
> ECOS는 일일 호출 한도가 있다. 실측 하한은 150회이고 통화 하나의 전체 백필이 약 146회다.
> **하루에 전체 백필은 한 통화만** 하는 것이 안전하다. 화면 상단의 "오늘 호출" 수로
> 확인할 수 있다(참고 지표이며 한도 판정은 출처 응답으로 한다).

## 구조

```
backend/src/
├── ingestion/      외부 데이터 소스 어댑터. 벤더 응답 타입이 이 계층 밖으로 새지 않는다
├── repository/     저장·조회. DB 방언 문법은 db/dialect.py 뒤에 격리
├── simulation/     순수 함수 계산. DB·HTTP에 의존하지 않는다
├── worker/         수집 실행 수명 — 언제 무엇을 돌릴지
├── observability/  관측 기록 — 무슨 일이 있었는지 어떻게 남길지
└── api/            REST·SSE 엔드포인트

frontend/src/
├── app/            Next.js App Router
├── components/     화면 구성 요소
├── stores/         Zustand 상태
└── lib/            API 클라이언트, 타입, 스트림 구독
```

`worker`와 `observability`를 나눈 이유는 관심사가 다르기 때문이다. 한 모듈에 넣으면 수집
수명 로직과 기록 포맷이 엉킨다.

### 로그

| 파일 | 내용 |
|------|------|
| `logs/backend.log` | 웹서버 표준출력 |
| `logs/collection.log` | 수집 전용 구조화 로그 (한 줄 JSON) |

섞지 않는다. 접근 로그와 뒤엉키면 운영자가 걸러내야 한다.

`logs/collection.log`에 `deposit_rate_revised`(예금 금리 수정 — 투자처·달·이전 값·새 값)가 보이면 출처가 발표값을 고친 것이다. 저장값은
바꾸지 않으므로, 이 사건이 나오면 008 FR-020의 잠정 규칙(최근 N개월을 잠정으로)을 반복으로 정한다.

`apt_trade_revised`(시·군·구·달·더함·해제·사라짐 수)는 잠정 달을 다시 받았을 때 실거래가 바뀐 기록이다 — 늦게 신고·해제된 거래다.
부동산 수집은 `apt_collection_started`·`_completed`·`_failed`(종류·시·군·구·구간)를 남긴다.

## 개발

```bash
# 백엔드
cd backend
.venv/bin/python -m pytest -q --cov=src   # 테스트 + 커버리지
.venv/bin/python -m mypy src              # 타입 (strict)
.venv/bin/python -m ruff check src tests  # 린트

# 프론트엔드
cd frontend
npm test && npx tsc --noEmit && npx eslint .
```

전체 테스트는 **네트워크 없이 통과한다.** 외부 API는 저장된 응답 픽스처로 검증하며,
테스트가 실제 API를 호출하면 규약 위반이다.

> **개발 서버를 띄운 채 통합 테스트를 돌리지 말 것.**
> 테스트가 같은 MySQL의 스키마를 드롭·재생성하므로, 그 사이 서버가 조회하면
> `Unknown column` 오류가 난다.

> **백엔드는 단일 워커로 띄운다.**
> 수집 워커가 애플리케이션 프로세스 안에서 돌기 때문에, 워커를 여럿 띄우면 프로세스마다
> 수집 태스크가 생긴다. DB 점유가 중복 실행은 막지만 확인 호출이 한도를 낭비한다.
> `be-start.sh`가 이미 `--workers 1`을 지정한다. 앱 수명(`lifespan`)이 띄우는 태스크는 여덟이다 —
> 환율 수집, 점유 회수, 주식 수집, 검색용 목록 갱신, 코인 목록 갱신, 가상자산 수집, 예금 금리 수집, 부동산 수집(안에서 실거래 줄과
> 목록 줄 둘 — 시·군·구 전체 이력이 행정구역 갱신을 막지 않는다).

## 개발 방식

이 저장소는 **Spec-Driven Development**([Spec Kit](https://github.com/github/spec-kit))로
개발한다. 코드를 쓰기 전에 명세를 쓰고, 명세에서 설계와 태스크를 유도한다.

```
specify → clarify → plan → tasks → analyze → implement
```

기능별 산출물은 `specs/NNN-<이름>/`에 있다. 각 기능의 **왜**는 거기에 적혀 있다 — 무엇을
만들었는지가 아니라 왜 그렇게 만들었고 무엇을 하지 않기로 했는지가 남는다.

`.specify/memory/constitution.md`가 최상위 규칙이다. 설계·구현·리뷰가 모두 여기에
종속되며, 충돌하는 관행은 무효다. 주요 원칙은 다음과 같다.

| 원칙 | 요지 |
|------|------|
| 비동기 우선 | 요청 경로에 동기 I/O 금지 |
| 데이터 소스 격리 | 벤더 응답이 도메인 계층에 노출되지 않는다 |
| 테스트 주도 | 테스트 → 실패 확인 → 구현. 커버리지 80% |
| 데이터 정합성 | 결측을 임의 보간하지 않는다. 확정값의 재현성을 보장한다 |
| 금융 계산 정확성 | 금액·비율은 `Decimal`, DB는 `DECIMAL`. `float` 금지 |

문서·주석·커밋 메시지는 한국어로 쓴다. 기술 용어와 코드 심볼은 원어를 유지한다.

**주식 출처는 잠정이다.** Yahoo는 2017년에 공식 API를 닫았고 지금 쓰는 경로는 문서화되지
않은 내부 엔드포인트다. 참조 구현(사용자의 Apps Script)이 쓰던 것을 그대로 이어받았으며,
**개인 이용이라는 전제에 기댄 사용자 승인 결정**이다. 도구를 공개하거나 여러 사용자에게
제공할 계획이 생기면 그 전제가 깨지므로 출처를 다시 정해야 한다. 어댑터를 교체할 때 손댈
지점은 `backend/src/ingestion/yahoo/` 한 곳이며, 정적 검사가 그 경계를 지킨다
(`tests/unit/test_layer_boundaries.py`).

**대시보드 출처도 잠정이다**(014). 지표는 주식과 같은 Yahoo 비공식 엔드포인트를 지수·원자재·VIX·시장 환율로 넓혀 쓰고, 뉴스는 세 사이트의 화면이 부르는 경로를 읽는다 — 네이버 증권은 robots.txt가 모두 막고 약관이 자동 수집을 금지하며, Yahoo Finance 약관도 허가 없는 자동 수집을 금지한다. 모두 **개인 이용 전제의 사용자 승인 결정**이다(`specs/014-market-dashboard/plan.md`의 Complexity Tracking, 2026-10-09). 뉴스는 칸마다 10분에 많아야 한 번 부르고, 저장·재배포하지 않으며(메모리에만), 제목·링크만 보이고 출처를 밝힌다. 어댑터는 `backend/src/ingestion/news/`, 지표 심볼은 `backend/src/ingestion/yahoo/market_symbols.py` 한 곳이다. 뉴스 칸이 "차단"이면 기다려도 풀리지 않는다 — `.env`의 `NEWS_USER_AGENT`를 지금 브라우저의 사용자 에이전트로 고치고 백엔드를 다시 띄운다. 출처 호출·실패는 `logs/collection.log`에 한 줄씩 남는다(`news_fetch`·`market_quotes_failed`·`market_quotes_partial`·`market_chunk_failed`·`commentary_fetch`). 지표 모달의 변화 까닭과 장중 시세도 같은 전제의 이탈이다(사용자 승인 2026-10-10) — 까닭은 지표마다 10분에 많아야 한 번, 장중은 일 60초·주 5분 동안 메모리에만 둔다.

**가상자산 출처도 잠정이다**(007). investing.com의 코인 목록·과거 시세 화면이 부르는 내부 API를 쓴다. 약관이 허가
없는 저장·사용을 금지하므로 Yahoo와 같은 **개인 이용 전제의 사용자 승인 결정**이다(`specs/007-crypto-investment-simulation/plan.md`의
Complexity Tracking). 어댑터는 `backend/src/ingestion/investing/` 한 곳이다.

**부동산 단지 화면 링크도 잠정이다**(010 반복 3). 단지 이름에서 Npay 부동산의 그 단지 화면(`fin.land.naver.com/complexes/{번호}`)을 열려고, 검색 칸이
부르는 단지 자동완성(공개되지 않은 내부 API)으로 네이버 단지 번호를 찾는다 — Yahoo·investing.com과 같은 **개인 이용 전제의 사용자 승인 결정**이다
(`specs/010-chart-price-overlay-history-layout/plan.md`의 Complexity Tracking). 단지 하나에 한 번 찾아 번호와 원본만 저장하고(`apt_complex_naver`),
못 찾거나 출처가 막히면 링크는 네이버 통합검색으로 물러난다. 어댑터는 `backend/src/ingestion/naver_land/` 한 곳이다. 브라우저형 사용자 에이전트와
`Accept-Language`가 있어야 한다(없으면 403·429).

- **일봉은 UTC 하루**다. 계산 끝은 마지막으로 마감된 UTC 하루(UTC 어제)이고, 출처가 주는 오늘의 일봉은 저장하지 않는다
- **코인 목록**은 출처가 보여주는 만큼(약 3,650개) 받아 DB에 두고, 마지막 성공 뒤 7일이 지나 처음 검색할 때 다시 받는다.
  한글 이름은 한국어 판에서 같은 식별자로 짝짓는다(한글 이름을 주는 코인은 12개 남짓이다)
- **호출 간격**: 요청 사이 1.5초(`INVESTING_MIN_INTERVAL_SECONDS`). 목록 갱신과 시세 수집이 이 간격을 함께 지킨다.
  403은 차단으로 보고 다시 시도하지 않는다

**키움은 검색용 종목 목록에만 쓴다**(006). 국내(KOSPI — ETF·리츠 포함, KOSDAQ)와 미국(NYSE·NASDAQ·
AMEX) 목록을 그날 처음 검색할 때(한국 시간) 받아 DB에 두고, 검색은 그 목록에서 한다. 시세·배당·분할은
위의 출처 그대로다 — 두 출처의 시세가 섞이지 않는다. 일본 종목은 키움이 지원하지 않아 Yahoo 검색을
그대로 쓴다.

- **이용 조건**: 키움증권 계좌 보유, HTS ID 연결, REST API 사용 등록. 미국 종목 목록에 해외주식 거래
  신청이 따로 필요한지는 문서에 없다. **이용약관 원문은 로그인 뒤에 있어 사용자가 확인했다**
  (2026-10-02). 개인 이용이 전제다 — 도구를 공개하거나 여러 사용자에게 제공할 계획이 생기면 다시
  따진다(006 research R6-15)
- **호출 한도**: 미국 목록은 계좌·토큰별 분당 5회. 단위마다 한 쪽에 끝나 실측으로는 걸리지 않는다.
  쪽 사이 간격(`KIWOOM_US_PAGE_DELAY_SECONDS`, 기본 12초)은 설정이다
- **비밀**: 앱 키·시크릿은 `.env`에만, 접근 토큰은 메모리에만 둔다. 목록 응답의 원본은 보관하되
  토큰 발급 응답과 요청·응답 헤더는 보관하지 않는다
- **계약 테스트 픽스처**: 실제 목록 응답을 저장소에 커밋했다(저장소가 비공개라 재배포가 아니다).
  저장소를 공개로 바꾸기 전에 검증에 필요한 행으로 줄인다

**예금 금리는 외환과 같은 ECOS다**(008). 약관이 무료·상업 이용을 허용하고, 의무는 출처 표시(제7조 ②)·과도한 호출 자제(제6조)·
인증키 관리(제4조)다. 화면 아래와 이 문서에 출처를 밝힌다.

- **투자처 ↔ 항목**: 시중은행은 예금은행 정기예금(1년)이라 **2012-01부터**다(정확히 1년인 항목이 그때부터 있다 — 일반·특수은행을
  합친 평균). 저축은행·신협·상호금융은 1997-08부터, 새마을금고는 2012-01부터다. 대응은 `backend/src/ingestion/ecos/deposit_items.py`
  한 곳에 있고, 항목 코드가 바뀌어도 이름 패턴으로 다시 찾는다
- **월별·익월 발표**: 이번 달과 지난달 금리는 대개 아직 없다. 그 달에 가입·재예치하면 마지막 발표 달 금리로 **잠정** 계산하고
  화면이 잠정임을 밝힌다(잠정 금리는 저장하지 않는다). 하루 한 번(한국 시간) 다시 확인하고, 겹쳐 받은 최근 2개월의 값이
  바뀌었으면 덮어쓰지 않고 `deposit_rate_revised` 사건만 남긴다
- **호출 한도를 환율과 함께 지킨다**: 환율 수집과 예금 수집은 다른 줄(서로 기다리지 않는다)이지만 ECOS 요청은 관문(`EcosGate`)
  하나를 지난다 — 동시 요청 수(`ECOS_MAX_CONCURRENT_REQUESTS`, 기본 3)를 함께 지키고, 한도 초과 신호가 오면 두 줄이 함께
  물러선다. 예금은 투자처마다 처음 한 번 전체 시계열, 그 뒤로 하루 한 번 짧은 구간이라 호출이 적다
- **인증키는 URL 경로에 들어간다** — 원본에는 응답 본문만 남기고, 실패 사유·수집 로그에서 키를 지운다

**부동산은 공공데이터포털이다**(009). 네 자료 모두 이용허락범위에 제한이 없고, 화면 아래와 이 문서에 출처를 밝힌다.

- **실거래 상세 자료**를 쓴다 — 기본 자료와 같은 거래에 단지 일련번호(`aptSeq`)·법정동 코드·본번·부번이 더 있어, 이름이 바뀐 단지와
  같은 이름 단지를 출처의 식별자로 가른다. 금액은 만원 쉼표 문자열이라 원 정수로, 전용면적은 소수 4자리까지 그대로 둔다
- **수집 단위는 시·군·구 × 계약 월**이다. 처음 고르는 시·군·구는 첫 거래 달(탐색 — 송파구는 2005-12)부터 이번 달까지 **전체 이력**(약
  260~280회)을 받는다 — 하루 한도(자체 계산 `DATA_API_DAILY_LIMIT_TRADE`, 기본 9,000 — 포털 10,000)로 하루 30곳 남짓이다. 한도에 닿으면 받은
  달까지 남기고 멈추며 다음 날 이어 받는다
- **잠정 12개월**: 해제가 늦게 신고된다(실측 — 해제의 75%가 2개월 안, 98.8%가 11개월 안). 최근 3개월은 하루 한 번, 4~12개월 전 달은 한 달에 한
  번 다시 받는다. 그 뒤의 해제(약 1.2%)는 반영하지 않는 한계다. 다시 받은 응답에서 사라진 거래는 지우지 않고 집계에서 뺀다
- **현존 시·군·구 코드만** 쓴다 — 출처는 과거 거래도 개편 뒤의 새 코드로만 주고, 사라진 코드에는 0건을 정상으로 준다(강원·전북
  특별자치도, 전남광주통합특별시 실측). 사라진 코드는 지우지 않고 그 코드의 거래를 집계에서 뺀다
- **단지 짝짓기**: 단지 목록(세대수·사용승인 연도)과 실거래 단지를 법정동 코드 + 지번, 아니면 그 동에서 하나뿐인 이름으로 한 행으로
  만든다. 큰 단지는 자료마다 대표 지번이 달라(헬리오시티 479 / 913) 이름으로 짝짓고, 건축년도와 사용승인 연도가 10년 넘게 다르면
  재건축 전후라 짝짓지 않는다
- **세법은 시행일별 표**다(`backend/src/simulation/apt_tax_rules.py` — 2006-01-01부터, 규칙마다 법령·조문·시행일). 세법이 바뀌면 새 규칙을
  더하고 현행 규칙의 끝을 닫는다. 표가 덮지 않는 날짜는 가까운 해로 메우지 않고 거절한다
- **인증키가 URL 질의(`serviceKey`)에 들어간다** — 원본에는 응답 본문만 남기고 URL은 저장하지 않으며, 실패 사유·수집 로그에서 키를 지운다
- **오류 종류**: 인증(게이트웨이 사유 20·30·31·32 — 키·활용신청), 한도(22·자체 한도 — 다음 날 이어 받기), 형식(12·잘림·읽을 수 없는 값 —
  어댑터 수정), 연결(그 밖 — 다시 실행). 게이트웨이 오류 본문은 자료 형식을 따른다 — 실거래는 XML, 나머지 셋은 JSON이다
