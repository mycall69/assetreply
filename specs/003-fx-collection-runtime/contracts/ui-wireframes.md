# Contract: UI 와이어프레임 — 003

**Feature**: 003-fx-collection-runtime | **Date**: 2026-09-24

002가 만든 수집 현황 화면(`/fx/collection`)을 **대체하지 않고 확장한다.** 전역 셸(사이드바·
상단바)과 진행 표시기는 002의 것을 그대로 쓴다.

와이어프레임은 **배치와 정보의 계층**을 정한다. 색·여백·타이포그래피는 구현에서 결정한다.

---

## W1. 수집 현황 화면 — 전체 배치

> 2026-09-24 반복으로 재작성했다. 세 통화를 쌓아 보여주던 구성을 **통화 선택 후 단일 통화
> 표시**로 바꿨다.

```

│           │  └────────────────────────────────────────────────────────┘  │
└───────────┴──────────────────────────────────────────────────────────────┘
```

**배치 규칙**

- **통화 선택기가 맨 위**에 온다. 아래 모든 내용이 선택에 종속되므로 종속의 방향이 배치로
  드러나야 한다.
- 선택한 통화의 카드 하나가 화면의 중심이다. 시간축 막대가 주인공이고 숫자는 막대 아래
  한 줄로 보조한다.
- 최근 기록도 **선택한 통화의 것만** 보여준다. 목록 제목에 통화를 명시해, 무엇을 보고 있는지
  스크롤 위치와 무관하게 알 수 있게 한다.
- 호출 수는 통화와 무관한 **전체 값**이다. 한도가 인증 키 단위라 통화별로 나뉘지 않는다.
  선택기 아래 한 줄에 두어 통화 카드와 구별한다.

**다른 통화가 수집 중일 때** (FR-029)

```
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 오늘 호출  37회                    [ 수집 시작 ]🚫     │  │
│  │ JPY를 수집하는 중입니다. 끝나면 USD를 시작할 수 있습니다│  │
│  └────────────────────────────────────────────────────────┘  │
```

시작 버튼을 막고 **어느 통화가 진행 중인지 이름을 댄다.** 버튼만 비활성화하고 이유가 없으면
사용자는 고장으로 여긴다. 진행 중인 통화 이름은 그 통화로 전환할 단서도 된다.

## W2. 시간축 막대 — 구간별 표현

막대 하나가 통화의 전체 대상 기간이다. 왼쪽 끝이 `targetFrom`, 오른쪽 끝이 `targetTo`다.

```
  1995 ──────────────────────────────────────────────────── 2026
  ████████████████████████████░▒▒░············
  └─────────── 수집 완료 ────┘ └┘ └── 미수집 ──┘
                              현재 구간
                          ▲
                    이어받은 지점
```

| 표현 | 의미 | 근거 |
|------|------|------|
| `█` 채움 | 수집 완료 구간 (`coveredFrom`~`coveredThrough`) | FR-012 |
| `▒` 진행 | 지금 받고 있는 구간 (`currentChunk`) | FR-013 |
| `·` 빈칸 | 아직 받지 않은 구간 | FR-012 |
| `▲` 표식 | 이어받은 지점 (`rangeStart`) | **FR-011** |

**이어받기 지점 표식이 이 화면의 핵심 요구다.** 이 표식이 없으면 사용자는 이어받기가 동작했는지
판단할 수 없다. 처음부터 수집하는 경우(`rangeStart == targetFrom`)에는 표식을 두지 않는다 —
모든 막대에 늘 표식이 있으면 의미가 사라진다.

**갱신**: 구간이 완료되면 `▒`가 `█`로 바뀌고 다음 구간이 `▒`가 된다(FR-014). 수집 스트림의
`snapshot`이 이 전환을 만든다.

## W3. 통화 카드 상태별 표현

카드 오른쪽 위 배지와 막대 아래 한 줄이 상태를 말한다.

| 상태 | 배지 | 막대 아래 한 줄 | 조작 |
|------|------|-----------------|------|
| 수집 이력 없음 | `수집 이력 없음` | 아직 수집하지 않았습니다 | `[ 수집 시작 ]` |
| 진행 중 | `진행 중` | `{rangeStart}`부터 이어받는 중 · `{done}/{total}` 구간 | 없음 |
| 처음부터 진행 중 | `진행 중` | `{done}/{total}` 구간 수집 중 | 없음 |
| 응답 없음 | `⚠ 응답 없음` | 60초 이상 진전이 없습니다. 회수를 기다리는 중이며 지금 하실 일은 없습니다 | 없음 |
| 회수 대기 | `⚠ 회수 대기` | 곧 부분 완료로 정리됩니다 | 없음 |
| 부분 완료 | `부분 완료` | `{coveredThrough}`까지 수집 · `{사유}` | `[ 이어받기 ]` |
| 완료 | `완료` | `{coveredThrough}`까지 수집 완료 | `[ 다시 확인 ]` |

**"지금 하실 일은 없습니다"가 FR-006a의 요구다.** 경고만 띄우고 설명이 없으면 사용자는 자기가
뭔가 해야 한다고 오해한다. 회수는 시스템이 하는 일이다.

**`[ 이어받기 ]`와 `[ 수집 시작 ]`은 같은 동작이다.** 문구만 상황에 맞춘다 — 이미 일부 받은
통화에 "수집 시작"이라고 쓰면 처음부터 다시 받는다는 오해를 준다.

## W4. 한도 소진 배너

한도가 소진되면 선택한 통화의 카드 위에 배너를 띄운다.

```
┌────────────────────────────────────────────────────────────┐
│ ⚠ 오늘의 호출 한도를 모두 썼습니다                          │
│                                                            │
│ USD 수집이 2024-03-16까지 받고 멈췄습니다. 지금까지 받은   │
│ 데이터는 그대로 유효합니다. 내일 이어받기를 누르면 멈춘    │
│ 지점부터 계속됩니다.                                       │
└────────────────────────────────────────────────────────────┘
```

> 2026-09-24 반복으로 축소했다. 원래는 세 통화가 동시에 멈추므로 전체 배너에 통화별 도달
> 지점을 요약했다. 한 번에 한 통화만 돌게 되면서 **진행 중이던 그 통화 하나만** 다루면 된다.

**"지금까지 받은 데이터는 그대로 유효합니다"는 FR-026의 요구다.** 이 문장이 없으면 사용자는
한도 소진을 데이터 손실로 오해한다.

한도는 인증 키 단위라 **다른 통화로 전환해도 소진 상태는 그대로다.** 전환한 통화의 화면에서도
시작 버튼이 막히고 같은 사유가 제시되어야 한다 — 전환하면 풀린다고 오해하면 헛수고를 한다.

## W5. 기록 불완전 표시

`eventsDropped > 0`인 작업의 기록을 볼 때 목록 위에 띄운다(FR-018b).

```
┌────────────────────────────────────────────────────────────┐
│ ⚠ 이 작업의 기록 3건이 저장되지 않았습니다                  │
│   아래 목록은 완전하지 않습니다. 수집 자체는 정상입니다.    │
└────────────────────────────────────────────────────────────┘
```

**두 번째 줄이 중요하다.** 기록 실패와 수집 실패는 다른 일인데, 경고만 보면 사용자가 데이터를
의심하게 된다. FR-018a가 "기록 실패가 수집을 중단시키지 않는다"고 정한 이상, 화면도 둘을
구별해야 한다.

`eventsDropped == 0`이면 이 영역을 **아예 렌더링하지 않는다.** 정상 상태에 "기록 완전함" 같은
표시를 두면 소음이 된다.

**사건 종류별 표기**

| `kind` | 표기 | 강조 |
|--------|------|------|
| `job_started` | 작업 시작 | 없음 |
| `chunk_requested` | 구간 요청 | 없음 |
| `chunk_stored` | 구간 저장 | 없음 |
| `chunk_empty` | **고시 없음** | 없음 |
| `chunk_failed` | **구간 실패** | 경고색 |
| `retry` | 재시도 | 주의색 |
| `rate_limited` | 한도 소진 | 경고색 |
| `job_finished` | 작업 종료 | 없음 |
| `log_sink_failed` | 파일 기록 실패 | 주의색 |

**`고시 없음`과 `구간 실패`를 다른 문구로 쓰는 것이 FR-021의 시각적 귀결이다.** 휴일이라 값이
없는 것과 수집이 실패한 것을 같은 색·같은 문구로 보여주면, 나중에 시계열 공백의 원인을 되짚을
때 기록이 아무 도움이 되지 않는다.

**보관 범위를 목록 하단에 명시한다**(FR-023). 오래된 기록이 없는 것이 고장이 아니라 설계임을
알린다.

## W7. 상단 진행 표시기 — 002의 것을 확장

002의 `CollectionIndicator`는 진행 중일 때만 나타나 통화 목록을 보여준다. 이번 기능에서
**멈춤 상태를 반영한다.**

| 상태 | 표시 |
|------|------|
| 정상 진행 | `● 수집 중 (USD)` — 한 번에 한 통화이므로 목록이 아니다 |
| 멈춤 | `⚠ USD 응답 없음` |
| 한도 소진 | `⚠ 한도 소진 — 수집 중단됨` |

표시기는 **진행 중인 통화**를 가리킨다. 사용자가 보고 있는 선택 통화와 다를 수 있으며, 그
경우 표시기를 누르면 진행 중인 통화로 전환되어야 한다 — 이름만 보여주고 갈 수 없으면 사용자가
직접 찾아야 한다.

표시기는 수집 현황 화면으로 가는 유일한 진입점이므로(002 research R2-10), **문제가 생겼을 때
그 사실이 여기서부터 드러나야 한다.** 표시기가 정상처럼 보이면 사용자는 화면에 들어올 이유를
찾지 못한다.

## 접근성

- 시간축 막대는 색만으로 구간을 구별하지 않는다. 완료·진행·미수집이 명암과 패턴으로도
  구별되어야 하며, 막대 전체에 진행률을 읽을 수 있는 텍스트 대체를 둔다.
- 상태 배지의 `⚠`는 장식이 아니라 의미를 지니므로 스크린 리더에서 읽혀야 한다.
- 한도 배너와 기록 불완전 경고는 알림 역할을 하므로 화면에 나타날 때 스크린 리더가 알린다.
- `[ 수집 시작 ]` 등 조작은 키보드로 접근·실행할 수 있어야 한다.
- 통화 선택기는 키보드로 이동·선택할 수 있어야 하고, 현재 선택이 보조 기술에 읽혀야 한다
  (002의 `CurrencyTabs`가 `role="tablist"`로 이미 충족한다).
- 시작 버튼이 막힌 경우 그 이유가 버튼과 함께 읽혀야 한다. 비활성 상태만으로는 이유를
  알 수 없다.

## 갱신 범위

수집 스트림의 `snapshot`이 도착했을 때 무엇을 다시 그리는지 정한다.

| 영역 | 갱신 |
|------|------|
| 시간축 막대 | 갱신한다 |
| 카드 상태 배지·설명 | 갱신한다 |
| 호출 수 | 갱신한다 |
| 한도 배너 | 상태 전이 시에만 |
| 최근 기록 | `event` 이벤트로 **앞에 덧붙인다**. 전체를 다시 받지 않는다 |
| 사이드바·상단바 | 표시기 외에는 갱신하지 않는다 |
| **통화 전환 시** | 시간축·카드·기록·경고를 **모두 비우고** 새 통화로 다시 채운다. 이전 통화의 값이 한 프레임이라도 남아서는 안 된다 (FR-028) |

기록 목록을 매번 전체 교체하면 사용자가 읽던 위치가 사라진다. 새 사건만 앞에 쌓는다.
