# Quickstart: 003 검증 시나리오

**Feature**: 003-fx-collection-runtime | **Date**: 2026-09-24

구현 완료 후 사람이 순서대로 실행해 결과를 기록한다. 자동 테스트가 덮지 못하는 것 —
프로세스를 실제로 죽였을 때의 회복, 화면을 떠났다 돌아오는 경험, 시간축이 실제로 채워지는
모습 — 이 검증의 대상이다.

## 사전 조건

| 항목 | 값 |
|------|-----|
| Python | 3.14.x (헌법 기술 스택) |
| 기동 | `./start.sh` (백엔드 8080 / 프론트엔드 3030) |
| DB | MySQL 8.0+, Alembic 최신 리비전 적용 |
| 출처 인증 | 프로젝트 루트 `.env`의 ECOS 키 |
| 서버 | **단일 워커 프로세스** (R3-1의 전제) |

**주의**: 이 검증은 실제 ECOS를 호출한다. 전체 백필이 통화당 약 146회이고 일일 한도 실측
하한이 150회이므로, **하루에 전체 백필은 한 통화만 한다.** 시나리오 9(한도 소진)를 제외하면
증분 수집 위주라 호출이 적다.

단일 통화 수집으로 바뀌면서 이 제약을 지키기가 오히려 쉬워졌다 — 한 번에 한 통화만 도므로
의도치 않게 세 통화를 동시에 백필하는 일이 없다.

---

## 1. 수집이 실제로 실행된다 (US1 / FR-001)

001·002에서 동작하지 않던 핵심을 먼저 본다.

1. 상단바의 `⟳ 수집 현황`을 눌러 들어간다. **주소를 직접 입력하지 않는다** — 진입 경로도
   검증 대상이다(FR-030).
2. JPY를 선택하고 `[ 수집 시작 ]`을 누른다.
3. 시간축 막대가 왼쪽부터 채워지기 시작하는지 본다.

**기대**: 막대가 진행한다. 진행률 0에서 멈추지 않는다.

---

## 2. 화면을 떠나도 계속 진행된다 (US1 / SC-001)

1. 시나리오 1이 진행 중인 상태에서 사이드바의 `외환`으로 이동한다.
2. 30초 기다린다.
3. `/fx/collection`으로 돌아온다.

**기대**: 떠나 있던 동안의 진행이 반영되어 있다. 떠난 시점보다 막대가 더 채워져 있다.

---

## 3. 브라우저를 닫아도 계속 진행된다 (US1 / SC-002)

1. 수집이 진행 중인 상태에서 브라우저 탭을 완전히 닫는다.
2. 1분 기다린다.
3. 브라우저를 다시 열고 `/fx/collection`에 들어간다.

**기대**: 수집이 중단되지 않았다. 완료됐거나 더 진행된 상태다.

---

## 4. 재진입 시 즉시 따라잡는다 (US2 / FR-010, SC-005)

1. 수집이 진행 중인 상태에서 화면을 새로 고친다.
2. 첫 화면이 그려지는 시점을 본다.

**기대**: 현재 진행 지점이 **3초 이내**에 표시된다. 다음 갱신을 기다리지 않는다.

---

## 5. 이어받기 지점이 보인다 (US2 / FR-011, SC-006)

1. 시나리오 1의 수집을 중간에 서버 재시작으로 끊는다(시나리오 7 참조).
2. 카드의 `[ 이어받기 ]`를 누른다.
3. 시간축의 `▲` 표식을 확인한다.

**기대**: 표식이 이전에 멈춘 지점에 있다. 그 지점부터 새로 채워진다. 처음부터 다시 받지
않는다.

---

## 6. 이미 받은 구간을 다시 받지 않는다 (FR-008, FR-009, SC-003)

1. 완료된 통화(EUR)의 `[ 다시 확인 ]`을 누른다.
2. 상단 호출 수를 누르기 전후로 비교한다.

**기대**: 작업이 즉시 완료로 끝나고 **호출 수가 늘지 않는다.**

---

## 7. 비정상 종료 후 회수된다 (FR-005, FR-005a, SC-010, SC-014)

1. 수집이 진행 중인 상태에서 백엔드를 강제 종료한다: `kill -9 $(cat logs/backend.pid)`
2. `./be-start.sh`로 다시 띄운다.
3. `/fx/collection`에 들어간다.

**기대**:
- 그 작업이 **부분 완료**로 정리되어 있다. 진행 중으로 남아 있지 않다.
- `[ 이어받기 ]`를 누르면 새 작업이 생기고 멈춘 지점부터 이어진다.
- 점유가 남아 시작이 막히지 않는다.

**참고**: `--reload`로 띄운 개발 환경에서는 백엔드 파일을 저장하기만 해도 같은 경로가
발동한다(R3-1).

---

## 8. 멈춤이 60초 안에 드러난다 (FR-006, FR-006a, SC-011)

1. 수집이 진행 중인 상태에서 백엔드 프로세스를 **정지**시킨다: `kill -STOP <pid>`
   (종료가 아니라 정지 — 하트비트만 멈춘다)
2. 화면을 보며 기다린다.

**기대**:
- 60초 이내에 카드가 `⚠ 응답 없음`으로 바뀐다.
- "회수를 기다리는 중이며 지금 하실 일은 없습니다"가 함께 보인다.
- 상단 표시기도 `⚠`로 바뀐다.

정리: `kill -CONT <pid>`로 재개시킨다.

---

## 9. 한도 소진 시 멈추고 사유가 남는다 (US4 / FR-025a, FR-026, SC-013a)

**호출을 많이 쓰므로 하루 한 번만 한다.**

1. 한 통화를 처음부터 수집해 한도를 소진시킨다.
2. 소진 시점의 화면을 본다.
3. **다른 통화로 전환**해 본다.

**기대**:
- 배너가 뜨고 그 통화의 도달 지점이 보인다.
- 작업이 부분 완료로 끝나고 사유가 한도임이 남는다.
- "지금까지 받은 데이터는 그대로 유효합니다"가 보인다.
- **다른 통화로 전환해도 소진 상태가 유지되고 시작 버튼이 막힌다.** 전환하면 풀린다고
  오해하면 헛수고한다.

**대체 검증**: 실제 소진이 어려우면 설정으로 한도 신호를 주입해 같은 경로를 확인한다.

---

## 10. 통화를 전환하면 이전 통화가 남지 않는다 (US2 / FR-028, SC-016)

> 2026-09-24 반복으로 교체했다. 원래는 통화 간 격리를 검증했으나 병행 수집이 사라졌다.

1. USD를 수집해 시간축과 기록이 채워진 상태로 만든다.
2. JPY로 전환한다.
3. 화면 전체를 살핀다 — 시간축, 상태 배지, 기록 목록, 경고 배너.

**기대**: USD의 값이 **어디에도 남아 있지 않다.** JPY의 상태로 완전히 바뀐다.

**까다로운 경우**: USD 수집이 진행 중일 때 전환하면, 전환 직후 USD의 갱신이 뒤늦게 도착할 수
있다. 그 값이 JPY 화면에 반영되어서는 안 된다. 002의 오늘 환율 새로고침에서 같은 결함을
겪었다.

---

## 11. 기록이 양쪽에 남는다 (US3 / FR-017, FR-018, SC-007)

1. 수집을 한 번 돌린다.
2. 화면의 `최근 기록`과 수집 로그 파일을 대조한다.

**기대**: 같은 사건이 양쪽에 있다. 한쪽에만 있는 사건이 없다.

---

## 12. 결측과 실패가 구별된다 (FR-021)

1. 휴일이 포함된 구간을 수집한다.
2. 기록에서 해당 구간을 찾는다.

**기대**: `고시 없음`으로 표기된다. `구간 실패`와 문구·색이 다르다.

---

## 13. 기록 실패가 수집을 멈추지 않는다 (FR-018a, FR-018b, SC-007a, SC-007b)

1. 이벤트 적재가 실패하도록 만든다(예: 이벤트 테이블에 일시적 제약 위반 유도).
2. 수집을 돌린다.

**기대**:
- 수집은 끝까지 진행된다. 환율 데이터가 정상 저장된다.
- 기록 목록 위에 `⚠ 이 작업의 기록 N건이 저장되지 않았습니다`가 뜬다.
- "수집 자체는 정상입니다"가 함께 보인다.

---

## 14. 보관 범위가 지켜진다 (FR-023, SC-015)

1. 한 통화로 21회 이상 수집을 돌린다(증분이라 각 회차가 빠르다).
2. 가장 오래된 작업의 기록을 조회한다.

**기대**: 최근 20개 작업의 사건만 남아 있다. 작업 행 자체는 21개 이상 남아 있다. 목록 하단에
보관 범위가 명시된다.

---

## 15. 비밀값이 남지 않는다 (FR-020, SC-009)

```bash
grep -ri "$(grep ECOS_API_KEY .env | cut -d= -f2)" logs/ 2>/dev/null | head
```

**기대**: 출력이 없다. 화면 기록에도 인증 정보가 나타나지 않는다.

---

## 16. 호출 수가 맞는다 (US4 / FR-024)

1. 수집 전 화면의 호출 수를 적는다.
2. 한 통화를 증분 수집한다(구간 수를 센다).
3. 수집 후 호출 수를 본다.

**기대**: 증가분이 실제 요청 구간 수와 일치한다. 화면에 "참고 지표"임이 명시된다.

---

## 17. 진행 중일 때 다른 통화 시작이 거절된다 (US1 / FR-029, SC-017)

1. USD 수집을 시작한다.
2. 진행 중에 JPY로 전환한다.
3. JPY의 `[ 수집 시작 ]`을 누른다.

**기대**:
- 화면 **전환 자체는 된다.** 진행 중인 통화에 갇히지 않는다.
- 시작 버튼이 막혀 있고 **"USD를 수집하는 중입니다"** 처럼 어느 통화인지 이름이 나온다.
- 조용히 무시되지 않는다. 버튼만 비활성이고 이유가 없으면 고장으로 여긴다.

---

## 18. 수집이 없어도 수집 현황에 갈 수 있다 (US1 / FR-030, SC-018)

**이 시나리오가 실패하면 나머지 전부가 무의미하다.** 수집을 시작할 방법이 없어진다.

1. 진행 중인 수집이 없는 상태에서 외환 화면(`/fx`)을 연다.
2. 상단바 우측을 본다.
3. 누른다.

**기대**:
- `⟳ 수집 현황`이 보인다. 수집이 없어도 사라지지 않는다.
- 누르면 `/fx/collection`으로 이동한다. **주소를 직접 입력하지 않고 도달한다.**
- 002의 외환 분석 화면에서도 같은 표시기가 보인다 — 어느 화면에서든 갈 수 있어야 한다.

---

## 19. 헌법 준수 확인

```bash
cd backend && .venv/bin/python -m pytest -q --cov=src
.venv/bin/python -m mypy src && .venv/bin/python -m ruff check src tests
cd ../frontend && npm test --silent && npx tsc --noEmit && npx eslint .
```

**기대**: 전부 통과, 커버리지 80% 이상, 네트워크 차단 상태에서도 통과.

추가 확인:

```bash
grep -rn "float(" backend/src/ | grep -v test    # 원칙 VI — 비어야 함
grep -rn "requests\.\|time\.sleep" backend/src/  # 원칙 I — 비어야 함
```
