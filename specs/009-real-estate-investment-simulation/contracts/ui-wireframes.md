# UI Wireframes: 부동산 투자 시뮬레이션

**Feature**: `009-real-estate-investment-simulation` | 근거: [rest-api.md](./rest-api.md), [research.md](../research.md) R9-10

화면은 주식(`/stocks`)·가상자산(`/crypto`)·예금(`/deposit`)을 본뜬다. 아래는 **그 셋과 다른 곳**만 그린다 — 나머지(매입일 입력의 달력·월·년
이동, 수집 안내의 진행 줄, 이력 비교)는 005~008과 같다. 금액은 통화 기호를 숫자 앞에 둔다(007 FR-042a), 차트 축은 천 단위 쉼표(007 FR-043a).

- 메뉴 순서는 그대로(외환 → 가상자산 → 주식 → 예금 → **부동산**), 부동산의 "준비중"이 사라진다. 상단 바 제목 "부동산"(FR-001)
- 지역은 **풀다운 셋**(시·도 → 시·군·구 → 법정동, `select`). 항목은 가나다순(FR-002, rest-api `regions`)
- 단지 풀다운의 항목은 "단지명 · YYYY년 입주 · N세대" — 세대수를 모르면 "단지명 · YYYY년 입주"만(지어내지 않는다, FR-003). 가구수 내림차순.
  **같은 동에 이름이 같은 단지가 둘 이상이면 항목 끝에 지번**을 붙인다 — "현대 · 1998년 입주 · 500세대 · 140", "현대 · 2003년 입주 · 140-2"
  (이름이 겹치지 않으면 지번을 붙이지 않는다). 지역 풀다운에는 현존 코드만 나온다(개편으로 사라진 코드는 없다, FR-002)
- 평형은 **라디오 일곱**(`fieldset`·`legend` "평형"), 각 항목에 해제를 뺀 거래 수. 거래가 0인 구분은 **비활성**과 "거래 없음"(FR-004). "ⓘ 전용면적
  경계"는 일곱 구분의 경계표를 펼친다(아래). 고른 구분 아래 한 줄 — 경계와 첫 거래 달
- 매입가는 선택 칸이다 — 비우면 매입 달의 시세(FR-006). 3자리 쉼표, 단위 "원". 통화 칸이 없다(FR-007)
- 화면 아래 출처 줄(FR-036, 헌법 원칙 II)

경계표(펼친 모양):

```

 20평대           50㎡ 이상 70㎡ 미만
 30평대(국평)      70㎡ 이상 85㎡ 이하      ← 국민주택규모 85㎡로 가른다
```

## E2. 고르는 순서와 기다림 (FR-002, FR-003, FR-011, FR-015)

- **상위를 바꾸면 하위를 비운다** — 시·도를 바꾸면 시·군·구·동·단지·평형과 결과를, 동을 바꾸면 단지·평형과 결과를 지운다. 이전 선택이 남은
  채로 실행할 수 없다(SC-007)
- 행정구역을 처음 받을 때(`regions` 202) — 지역 풀다운 자리에 "⟳ 행정구역 목록을 받고 있습니다 | 3 / 21쪽", 끝나면 시·도 목록이 채워진다.
  **그 수집이 실패하면** 지역 풀다운 자리에 경고(`role="alert"`) — "⚠ 행정구역 목록을 받지 못했습니다. 공공데이터포털 인증에 실패했습니다. —
  인증키 설정과 활용신청을 확인하세요."(종류별 문구·할 일은 E9 표). 풀다운은 비활성이고, 다시 시도는 화면을 다시 열 때다 — 다음 `regions`
  요청이 새 작업을 시작한다(008과 같다, FR-015). 받아 둔 목록이 있으면(30일 갱신 실패) 그 목록을 그대로 쓰고 경고하지 않는다
- 동을 고르면 단지 목록이 곧바로 나온다(단지 목록 자료). 기본 정보를 채우는 동안 풀다운 아래에 "⟳ 세대수·입주년도를 채우고 있습니다 | 12 /
  47단지" — 끝나면 항목에 세대수가 붙는다
- 그 시·군·구의 실거래를 받은 적이 없으면 동을 고를 때 수집이 시작된다 — 단지 풀다운 아래 "⟳ 송파구 실거래를 받고 있습니다 | 120 / 250개월
  · 끝나면 단지 목록에 없던 단지가 더해집니다". 평형의 거래 수는 실거래를 다 받은 뒤 채워진다(그 전에는 평형 칸이 "실거래를 받은 뒤 고를 수
  있습니다"). 수집 중에 다른 화면으로 가도 수집은 이어진다
- 처음 고르는 시·군·구는 **전체 이력(약 280회 호출)**을 받는다 — 진행 줄 아래 작은 글자로 "처음 고르는 시·군·구는 전체 이력을 받습니다(하루
  한도로 30곳 남짓)"(research R9-5)
- 실거래 수집이 실패했으면(`trades.state = "failed"`) 단지 풀다운 아래에 E9의 실패 문구와 할 일(`role="alert"`) — 화면을 다시 열어도 사유가
  보인다(FR-014). 평형 칸은 "실거래를 받은 뒤 고를 수 있습니다"로 남는다
- 목록을 받지 못하면 빈 풀다운 대신 사유(`role="alert"`) — "단지 목록을 받지 못했습니다(인증키 오류). 실거래를 받은 단지만 보입니다."(FR-015)
- 단지를 바꾸면 평형·결과를 지운다. 실행은 버튼으로 한다(주식·예금과 같다)

## E3. 실행의 거절 (FR-005, FR-006, FR-023)

```
 ⚠ 이 단지의 30평대(국평) 거래는 2019-01부터 있습니다. 매입일을 2019-01-01 이후로 고르세요.   [2019-01로 옮기기]
 ⚠ 세법 표는 2006-01-01부터 있습니다(첫 거래는 2005-12). 매입일을 2006-01-01 이후로 고르세요.   [2006-01로 옮기기]
 ⚠ 2019-05에는 30평대(국평) 시세가 없습니다(36개월 안에 거래 없음). 실제 매입가를 넣으면 계산할 수 있습니다.
 ⚠ 이 단지의 시·군·구가 행정구역 개편으로 바뀌었습니다. 지역에서 다시 골라 실행하면 새 코드로 받습니다.
```

- 409 `before_first_trade`는 006과 같은 안내와 옮기기 수단 — 조용히 옮기지 않는다(FR-005). 근거(`basis`)가 `first_trade`면 첫 거래 달,
  `tax_rules`면 세법 표의 첫 날을 밝힌다. 매입일 달력의 하한은 `areas`의 `startableFrom`이다
- 409 `no_price_at_purchase`는 매입가 칸으로 초점을 옮긴다(FR-006). `no_trades_in_area`는 "이 단지에 30평대(대형) 거래가 없습니다"
- 409 `tax_rule_not_covered`(보유 중의 과세기준일이 표 밖 — 표가 오늘까지 덮으므로 표가 낡았을 때만)는 세목과 날짜를 밝힌다(FR-023 — 가까운
  해로 대신하지 않는다)
- 409 `region_retired`는 단지의 시·군·구 코드가 개편으로 사라졌고 새 코드로 아직 받지 않은 경우다(이력의 다시 실행 등). 개편 사실과 "지역에서
  다시 골라 실행"을 보인다 — 조용히 "거래 없음"으로 보이지 않는다(FR-002, data-model 2절)

- **부동산 전용 보드**(`RealEstateBoard`)다 — 칸이 여섯이라 `PerformanceBoard`(원금·수익·수익률)를 늘리지 않는다(research R9-10). 기호 위치·

- 매입가 칸 아래: 직접 넣었으면 "직접 입력", 아니면 쓴 창·건수(추정이면 "추정")
- 평가액 칸 아래: 쓴 창·건수, 추정·잠정 글자(FR-030)
- 기준 줄: 단지·평형·매입일·가정 넷(FR-030). 매입가를 직접 넣었으면 "매입가 직접 입력"을 더한다

보드 아래 줄(`role="status"`, 순서대로 — 해당할 때만. 아래 "지금 시세 없음"·"보유세 계산 불가"는 다른 단지·평형의 예다 — 헬리오시티
30평대(국평) 2021-03 매입에서는 나오지 않는다):

```
 ⚠ 오늘 실거래 확인에 실패했습니다(호출 한도 초과) — 받아 둔 거래로 계산했습니다. 내일 다시 확인합니다.
```

- 잠정 줄은 잠정 기간(최근 12개월)과 "바뀔 수 있다"와 그 이유 둘을 담는다(FR-010, FR-018). 지금 시세 없음 줄은 마지막 시세 달을 밝힌다(FR-026). 보유세 계산 불가 줄은 그 해들을
  모두 적는다(`summary.taxGaps`, FR-021). 확인 실패 줄은 008 D3과 같다 — 인증이면 "인증키 설정을 확인하세요.", 형식이면 "출처의 응답 형식이
  바뀌었습니다 — 어댑터를 고쳐야 합니다."를 붙인다(FR-014)

- **세금의 기준 시세**(그해 6월)가 추정이면 세금 아래 작은 글자로 "6월 시세 추정", 잠정이면 "6월 시세 잠정"을 붙인다. 칸의 `title`에 기준
  시세·창·건수("2025-06 시세 2,400,000,000 · 3개월·7건")를 넣는다(FR-021, rest-api `basis`)
- 최신순, 한 번에 모두(20년이어도 240행 남짓). 열 폭은 내용에 맞추고 브라우저 창 1440px에서 가로 스크롤이 없다(FR-028, SC-010)

```
 평가액(KRW) 2,450,000,000 ┤                     ○  ○        ╭──┄┄┄   ├ 20.00   범례: ─ 평가액 (KRW)  ╌ 수익률 (%)
             2,000,000,000 ┤──╮───╭──╯  ╰──╮──────────╭────╯          ├ 0.00          ○ 추정 시세(1개월 밖의 창)
                                                                                         ┄ 잠정(2025-11부터)  ⋯ 시세 없음(끊음)
```

- `PerformanceChart`를 그대로 쓴다. 시세 없음 달은 `gaps`(`no_price`)로 끊는다 — `splitSeriesAtGaps`가 이 사유를 미수집처럼 끊게 한다(앞뒤를
  잇지 않는다). 위 그림(30평대(국평))에는 시세 없음 달이 없다 — 50평대처럼 시세 없음 달이 있으면 그 구간에서 선이 끊기고 범례 "⋯ 시세 없음
  (끊음)"이 그 뜻을 밝힌다
- 잠정은 008의 `provisionalFrom`(연한 색)을 그대로 쓴다
- **추정 점은 표식(속이 빈 원)**이다 — 시계열 점의 선택 키 `estimated`가 참인 점에만. 범례 "○ 추정 시세(1개월 밖의 창)". 주식·가상자산·예금은
  이 키가 없어 지금과 같다(research R9-10)
- 점은 매달이고 값은 표의 그 달 평가액·수익률이다. 첫 점은 매입일, 끝점 = 보드(FR-031, SC-009)

## E8. 설정 — 부동산 보유세 기준 비율 (FR-034)

```
 예금
   이자 소득세        [ 15.4  ] %
 부동산
   보유세 기준 비율    [ 60    ] %   (기본값 — 실거래 시세의 60%를 공시가격으로 본다)
                                    [ 저장 ]
```

- 다른 자산군 설정과 **따로** 저장한다. 0 초과 100 이하가 아니거나 숫자가 아니거나 소수 4자리를 넘으면 저장하지 않고 사유를 보인다(FR-034 —
  비율로 소수 6자리, 008과 같은 자릿수 규칙)
- 저장 뒤 "저장했습니다. 부동산 화면으로 돌아가면 새 값으로 다시 계산합니다."(008과 같다). 기본값과 다르면 "기본값으로"

## E9. 수집 안내와 실패 (FR-011, FR-014)

```
 ⟳ 송파구 실거래를 받고 있습니다 | 120 / 250개월
 ⚠ 실거래 출처의 하루 호출 한도에 닿았습니다. 받은 데까지 남겼습니다 — 내일 다시 실행하면 이어서 받습니다.
```

| 종류 | 문구 | 할 일 |
|------|------|-------|
| `auth` | 공공데이터포털 인증에 실패했습니다. — 인증키 설정과 활용신청을 확인하세요. | 설정 수정 |
| `rate_limited` | 실거래 출처의 하루 호출 한도에 닿았습니다. 받은 데까지 남겼습니다. | 내일 다시 실행 |
| `format` | 출처의 응답 형식이 바뀌었습니다. — 어댑터를 고쳐야 합니다. | 코드 수정 |
| `network` | 출처에 연결하지 못했습니다. 다시 실행하면 이어서 받습니다. | 다시 실행 |

- 진행 줄은 006 `CollectingNotice`와 같다 — 주어 "송파구 실거래", 단위 "개월"(008이 더한 선택 속성)
- 받을 달은 그 시·군·구의 첫 달(모르면 탐색 시작 달) ~ 이번 달이다. 처음 받는 시·군·구는 탐색 중 거래 없는 달도 센다
- **받아 둔 시·군·구의 잠정 확인이 실패하면 화면이 곧바로 한 번 다시 요청한다**(008 FR-016a와 같다) — 받아 둔 시·군·구는 단지 목록 응답의
  `trades.state`가 `collected`인 곳(첫 달부터 잠정 기간 앞 달까지 모두 받음)이다. 서버가 받아 둔 거래로 계산해 200 + `recheckFailed`를 주므로
  결과와 보드 아래 확인 실패 줄(E4)이 남는다. 받은 적 없거나 중간까지만 받은 시·군·구는 다시 요청하지 않는다(서버도 200을 주지 않는다 — 부분
  결과, FR-011)
- 한도 초과는 하루 한도(설정) 자체 계산으로 출처가 막기 전에 멈춘 것이다(SC-012). 받은 달은 커버리지에 남아 다음 실행이 이어 받는다

## 접근성

- 지역·단지는 `label`이 붙은 `select`다. 평형 라디오는 `fieldset`·`legend`("평형")로 묶고 각 항목의 경계 줄을 `aria-describedby`로 잇는다.
  비활성 항목은 `disabled`와 글자 "거래 없음"
- 보드 아래 줄은 알림 역할(`role="status"`), 실패·거절은 경고 역할(`role="alert"`)이다(005~008과 같다)
- 표의 추정·잠정·분납 표시는 글자다. 손익은 부호와 함께(`+14.68%`, `-₩…`)
- 수집 진행 막대는 `role="progressbar"`와 값·범위를 가진다(006 `CollectingNotice`)
