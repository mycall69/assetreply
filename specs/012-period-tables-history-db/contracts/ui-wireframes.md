# 화면 계약 (012)

**Date**: 2026-10-06 | **Research**: [../research.md](../research.md) R12-1·R12-8·R12-13·R12-14

화면은 계산하지 않는다. 값·표시는 서버 응답 그대로 그린다(011 `noClientSideFinance`). 기호만으로 전달하지 않는다 — 기호마다 `title`·`aria-label` 글자 설명을 두고
표 아래에 범례를 둔다(spec FR-010).

## F1. 외환 일자별 표 — 기간 전환 (US1)

화면 모양은 바뀌지 않는다. 동작만 바뀐다.

| 동작 | 지금 | 012 |
|------|------|-----|
| 일·주·월 누름 | 표가 떨어졌다 붙고, 붙은 뒤 창이 표의 처음으로 간다 | 표가 떨어졌다 붙는 동안 높이를 붙잡는다. **창은 움직이지 않는다** — 단위 탭이 누른 자리에 남는다. 새 표가 짧아도 스크롤 위치를 받칠 높이를 남긴다 |
| 먼 날짜 고름(FR-005a) | 표의 처음으로 | 그대로 |
| 통화 바꿈 | 높이를 붙잡고 창은 그대로 | 그대로 |

## F2. 주식·가상자산 일자별 투자 성과 표 — 머리 (US2)

```text
┌ 일자별 투자 성과 ─────────────────────────── [ 일 | 주 | 월 ] ┐   ← 외환과 같은 탭(role="tablist", aria-label="기간 단위 선택")
│ ⚠ 2026-10-02 이후 시세가 없습니다. …  (지금의 table-asof — 그대로)            │
│ 날짜 │ 구분 │ … 지금 열 그대로 …                                               │
```

- 탭 제목(`title`):
  - 주식: 일 "시세가 있는 날마다" · 주 "그 주의 금요일 (없으면 그 앞의 마지막 거래일)" · 월 "그 달의 말일 (없으면 그 달의 마지막 거래일)"
  - 가상자산: 일 "일봉마다" · 주 "그 주의 금요일 일봉 (없으면 그 앞의 마지막 일봉, 월~금에 없으면 그 주의 마지막 일봉)" · 월 "그 달의 말일 일봉 (없으면 그 달의 마지막 일봉)"
- 처음 단위는 "일"이다. 다시 실행해도 고른 단위가 남는다. 새로 고치면 "일"이다.
- 일시금·적립식 표 넷에 모두 둔다. 보드·차트·이력 칸에는 손대지 않는다.

## F3. 행 표시와 범례 (US2)

날짜 칸 옆에 붙는다(외환 `PeriodRowBadges`와 같은 모양).

| 기호 | 붙는 행 | 글자 설명(`title`·`aria-label`) |
|------|---------|----------------------------------|
| 📅 | `shiftedFrom`이 있는 행 | 주식: "기준일 10-09(금)에 시세가 없어 10-05 값입니다" · 가상자산: "기준일 10-09(금)에 일봉이 없어 10-08 값입니다". 월은 "(말일)" |
| ⏳ | `isOngoing`인 행 | "이번 주가 아직 끝나지 않았습니다" · "이번 달이 아직 끝나지 않았습니다" |
| ＋ · ◆ · ⟳ | 사건 행 | 지금 그대로(납입·배당락·재투자) |

- 둘이 한 행에 함께 붙을 수 있고 서로 구별된다(spec FR-004a — 004 FR-015b).
- 범례는 표 아래에 둔다. 주·월이면 "📅 기준일이 옮겨진 행 · ⏳ 아직 끝나지 않은 구간"이다. 일이면 범례가 없다(표시가 없다).
- 사건 행이 그 구간의 대표 행이면 그 사건 행에 표시가 붙는다(spec FR-005).
- ◇(1일 결측)는 없어진다(spec FR-008).

## F4. 결측 구간 행 — 가상자산 일 단위 (US2)

```text
│ 10-04 │       │ 63,210,000 │ …                                        │
│ 2026-10-02~10-03 출처 결측 — 값 없음                                    │   ← 한 칸에 걸친 글(colSpan), 연한 회색 바탕, 값 칸 없음
│ 10-01 │       │ 61,980,000 │ …                                        │
```

- `role="row"` 안에 한 칸이고, 날짜와 사유가 한 덩어리의 글이다 — "처음~끝 출처 결측 — 값 없음". 같은 해면 끝의 해를 줄이고(`2026-10-02~10-03`),
  하루면 그날 하나다(`2026-10-02 출처 결측 — 값 없음`). 값을 메우지 않는다.
- 주·월 단위에는 없다. 주식 표에는 없다(휴장은 결측이 아니다).

## F5. 단위 전환 중 (US2)

- 표의 행만 비우고 "⟳ 불러오는 중…"(`role="status"`)을 보인다. 보드·차트는 그대로다.
- 바꾸는 동안 작업 영역의 높이를 붙잡는다(F1과 같은 훅). 창은 움직이지 않는다.
- 늦게 온 이전 단위의 응답은 버린다. 실패하면 표 자리에 오류 문구와 다시 시도를 보이고, 고른 단위는 남는다.

## F6. 최근 시뮬레이션 칸 (US3)

```text
┌ 최근 시뮬레이션 ────────────────────────────────────────┐
│ ⓘ 이 기기의 로컬 DB에 저장됩니다. 마지막 실행 뒤 30일이 지나면    │   ← data-testid="history-notice"
│   지워집니다 — 기간은 설정에서 바꿉니다. 주식 이력과 따로입니다.    │      (자산군 구별 문구는 지금 그대로)
│ □ 삼성전자 · 2020-01-02 · 10,000,000원 · 재투자    [다시 실행] [×] │
```

| 상태 | 보이는 것 |
|------|-----------|
| 불러오는 중 | "⟳ 불러오는 중…" — 빈 상태 문구를 보이지 않는다 |
| 불러오기 실패(FR-014a) | `role="alert"` "이력을 불러오지 못했습니다." + **다시 시도** 단추. "아직 실행한 시뮬레이션이 없습니다"를 보이지 않는다 |
| 빈 목록 | "아직 실행한 시뮬레이션이 없습니다."(지금 그대로) |
| 저장 실패(FR-014) | `role="alert"` "이력을 저장하지 못했습니다. 결과는 그대로이고, 다시 실행하면 다시 저장합니다." |
| 삭제 실패 | `role="alert"` "이력을 지우지 못했습니다." |
| 옮기지 못한 항목 | `role="status"` "읽을 수 없는 브라우저 이력 N개는 옮기지 못했습니다." |
| 무기한 | 안내의 둘째 문장이 "기한 없이 남습니다."다 |

항목 줄·다시 실행·삭제·비교는 지금 그대로다.

## F7. 설정 — 이력 보관 기간 (US3)

설정 화면 맨 아래에 절 하나를 더한다.

```text
┌ 최근 시뮬레이션 이력 ─────────────────────────────────────┐
│ 보관 기간  [ 30일 ▾ ]   (7일 · 30일 · 90일 · 180일 · 365일 · 무기한) │
│ ⓘ 마지막 실행 뒤 이 기간이 지난 항목은 지워집니다. 기간을 줄이면    │
│   그보다 오래된 항목이 곧바로 지워지고, 다시 늘려도 돌아오지 않습니다. │
│ [저장]                                   기본값: 30일             │
└──────────────────────────────────────────────────────────┘
```

- 저장하면 "저장했습니다. 기간이 지난 항목은 곧바로 지웠습니다."를 보인다(다른 절의 알림과 같은 자리).
- 실패하면 붉은 `role="alert"` 상자에 서버 메시지를 보인다(다른 절과 같다).

## F8. 투자 원금 칸 (US4)

- 주식·가상자산·예금 화면을 처음 열면 칸이 "10,000,000"이다.
  - 쉼표는 지금의 표시 형식 그대로다. 저장값은 `"10000000"`이다.
  - 통화는 원화다. 예금 칸 뒤의 "원"은 지금 그대로다.
- 이름표만 방식·상품에 따라 바뀐다("투자 원금" · "한 번 납입액" · "월 납입액"). 값은 그대로다.
- 부동산 화면은 바뀌지 않는다.

## F9. 성과 보드의 현재 잔고 (US5 — 반복 2026-10-07)

| 보드 | 칸(차례) |
|------|----------|
| 주식 일시금 | 투자 원금 · **현재 잔고** · 매도 수수료/세금 · 투자 수익 · 수익률 |
| 가상자산 일시금 | 투자 원금 · **현재 잔고** · 투자 수익 · 수익률 |
| 주식·가상자산 적립식 | 총 납입 원금 · **현재 잔고** · 매매 수수료 총액 · 세금 총액 · 투자 수익 · 수익률 |
| 예금·정기 적금·부동산 | 그대로 |

```text
┌ 투자 원금 ──────┬ 현재 잔고 ─────┬ 매도 수수료/세금 ┬ 투자 수익 ──────┬ 수익률 ─────┐
│ ₩10,000,000     │ ₩14,630,000    │ -₩119,299        │ ₩4,510,701      │ +45.11%     │
│                 │                │ 수수료 · 세금     │ 보유 중 ₩4,630,000 │ 보유 중 …   │
└─────────────────┴────────────────┴──────────────────┴─────────────────┴─────────────┘
```

- 칸 이름은 "현재 잔고"이고 `role="group"`·이름은 칸 이름이다(다른 칸과 같다).
- 값은 서버의 `summary.totalKrw`를 원화 기호로 그린다(`₩14,630,000`). 원금 통화가 USD여도 원화만이다. 손익 색을 쓰지 않는다.
- 칸 안의 설명 한 줄: 일시금 "잔고 + 예수금", 주식 적립식 "잔고 + 매수 대기금 + 배당 현금", 가상자산 적립식 "잔고 + 매수 대기금" — 표의 "잔고" 열(보유 평가액)과 다른
  까닭을 보인다.
- 일시금 보드는 `totalKrw`가 있을 때만 이 칸을 그린다 — 같은 부품을 쓰는 예금 보드는 그대로다.

## F10. 해외 주식 매도 칸의 양도차익 구성 (US6 — 반복 2026-10-07)

일시금 보드의 매도 칸(해외 종목 — XLK 2010-02-11 원화 2,000만 원 재투자, 2026-10-06 기준):

```text
매도 수수료/세금
-₩110,182,526
수수료 ₩80,884
양도소득세 22% ₩110,101,642
매도금액 ₩539,229,405 − 취득가 ₩36,181,082 − 수수료 ₩86,311      ← 더한 줄 1
취득가는 모든 매수(배당 재투자 포함) · 예수금은 팔지 않음           ← 더한 줄 2
차익 ₩502,962,012 − 공제 ₩2,500,000
세율·공제: 설정값(설정 > 주식 매도 세금)
```

- 주식 적립식 보드의 세금 칸(해외 종목): "양도소득세 … (설정)" 다음에 같은 구성 줄 1과 "취득가는 모든 매수(납입·배당 재투자) · 매수 대기금은 팔지 않음", 그 뒤 "차익 … − 공제 …".
- 값은 서버의 `saleKrw`·`acquisitionKrw`·`feesKrw`를 원화 기호로 그린다. 셋 가운데 하나라도 없으면(국내 종목·010 전 응답) 두 줄을 그리지 않는다.
- 국내 종목(증권거래세)·가상자산·예금·부동산은 그대로다.
