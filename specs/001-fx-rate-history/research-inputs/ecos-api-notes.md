# ECOS API 검증된 기술 사실 (계획 단계 입력)

기존에 동작하던 Google Apps Script 구현에서 확인된 내용이다. spec.md는 구현 세부사항을 담지
않으므로 여기에 분리해 둔다. `/speckit-plan`의 research 단계에서 이 문서를 입력으로 사용한다.

**출처**: 사용자가 제공한 기존 Apps Script (`ECOS FX: Base-only + Derived by Spreads`)
**확인 시점**: 2026-08

## 엔드포인트

```
https://ecos.bok.or.kr/api/StatisticSearch/{API_KEY}/json/kr/{startRow}/{endRow}/{통계표코드}/{주기}/{시작일YYYYMMDD}/{종료일YYYYMMDD}/{항목코드}
```

- 호스트는 `ecos.bok.or.kr`다 (BOK = Bank of Korea).
- 통계표코드: `731Y001`, 주기: `D`(일별)
- 항목 목록 조회: `https://ecos.bok.or.kr/api/StatisticItemList/{API_KEY}/json/kr/1/10000/{통계표코드}/`

## 항목코드

| 통화 | 항목코드 | 항목명 | 비고 |
|------|----------|--------|------|
| USD | `0000001` | 원/미국달러(매매기준율) | |
| JPY | `0000002` | 원/일본엔 | **100엔당 원화로 고시** |
| EUR | `0000003` | 원/유로 | |

**항목코드는 변경될 수 있다.** `StatisticItemList`로 목록을 조회해 이름 패턴
(미국달러 / 일본엔 / 유로)으로 검증하고, 불일치 시 이름으로 재탐색하는 경로가 필요하다.

**주의**: `StatisticItemList` 응답의 필드명은 `ITEM_CODE` / `ITEM_NAME`이다.
`ITEM_CODE1` / `ITEM_NAME1`이 아니다 — 기존 구현이 이 지점에서 자동탐지에 계속 실패했다.

## 응답 행 필드

| 필드 | 내용 |
|------|------|
| `TIME` | 날짜, `YYYYMMDD` 형식 |
| `DATA_VALUE` | 값. **쉼표가 포함된 문자열로 올 수 있다** |
| `UNIT_NAME` | 고시 단위 |
| `ITEM_NAME2` | 세부 항목명. 매매기준율 외 항목이 섞여 올 수 있어 필터링이 필요하다 |
| `list_total_count` | (컨테이너 필드) 조건에 맞는 전체 건수 |

## 오류 처리 — 가장 중요한 함정

**ECOS는 오류도 HTTP 200으로 반환한다.** 본문의 `{"RESULT": {"CODE": ..., "MESSAGE": ...}}`를
반드시 검사해야 한다. HTTP 상태 코드만 보면 오류를 성공으로 오인해 빈 데이터를 저장하게 된다.

| CODE | 의미 | 처리 |
|------|------|------|
| `INFO-100` | 인증키 오류 | 재시도 무의미. 즉시 실패 처리 |
| `INFO-200` | 해당 구간 데이터 없음 | **정상 응답으로 취급** (오류 아님) |
| `INFO-300` | 호출 한도 초과 | 백오프 대상 |
| `ERROR-*` | 기타 오류 | 상황에 따라 재시도 |

**JSON이 아닌 응답**은 차단 페이지 또는 점검 안내 HTML이다. JSON 파싱 실패를 위 오류들과
별개의 유형으로 구분해야 한다.

## 페이징과 호출량

- `startRow` / `endRow`로 요청 행 범위를 지정한다.
- `list_total_count`로 조건에 맞는 전체 건수를 알 수 있다.
- 기존 구현은 1회 `PAGE_SIZE = 100000`을 사용해 통화당 1회 호출로 전 구간을 받았다.
- 1995~현재 전 구간은 **통화당 약 8,400건**이다.
- **단, 호출 제한을 고려해 전 구간을 한 번에 요청하지 않기로 했다** (spec FR-008).
  구간을 나누어 순차 요청하되, 구간 크기·대기 시간·동시 요청 수는 설정값으로 둔다 (FR-009).

## 계획 단계에서 확인이 필요한 항목

1. **ECOS 공식 호출 한도**: (a) 1회 요청 최대 행 수, (b) 일일 호출 한도, (c) 초당/분당 제한.
   구간을 잘게 쪼개면 응답 크기·타임아웃 위험은 낮아지지만 **호출 횟수가 늘어 일일 한도를
   더 빨리 소진한다.** 이 트레이드오프를 실제 수치로 판단해 기본 구간 크기를 정한다.
2. **최초 백필과 증분 수집의 기본값 분리 여부**: 최초 백필은 통화당 약 8,400건,
   일상 증분은 수 건~수십 건이다. 같은 설정을 쓰는 것이 적절한가?
3. **731Y001의 실제 최초 제공일**: 1995-01-01부터 실제로 제공되는지 확인한다.

## 인증

인증키는 환경변수 `ECOS_API_KEY`로 주입한다. 코드와 저장소에 하드코딩하지 않는다
(헌법 원칙 II).
