# Feature Specification: FX 환율 축적·조회·시각화

**Feature Branch**: `001-fx-rate-history`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "FX(외환) 환율 수집·축적·조회·시각화 기능. 한국은행 ECOS를 통해 USD, JPY, EUR의 원화 매매기준율을 1995-01-01부터 축적하고, 통화와 날짜를 선택하면 그날의 환율(매매기준율 + 스프레드 적용 파생 환율)을 조회하며, 선택한 기간의 환율 추이를 차트로 볼 수 있게 한다. 데이터가 없으면 마지막 저장 날짜 다음날부터 오늘까지 자동으로 수집한다."

## Clarifications

### Session 2026-08-30

- Q: 과거 날짜의 파생 환율에 현재 스프레드를 적용하는가, 시점별 스프레드 이력을 적용하는가? → A: 현재 설정된 스프레드 하나를 모든 과거 날짜에 적용하고, 적용된 스프레드 값을 결과에 함께 표시·기록한다
- Q: 조회가 수집을 유발할 때 결과를 대기시키는가, 진행 상태를 먼저 보여주는가? → A: 필요한 구간이 임계값(기본 30일) 이하면 대기 후 즉시 결과, 초과하면 진행 상태 화면을 먼저 제시하고 완료 후 결과 갱신
- Q: 고시가 없는 날(주말·공휴일)을 조회하면 무엇을 보여주는가? → A: "고시 없음"을 주 결과로 제시하고, 직전 영업일의 값과 날짜를 시각적으로 구분되는 별도 참고 영역에 표시
- Q: 같은 통화의 수집 작업이 이미 진행 중일 때 수집이 다시 요청되면 어떻게 하는가? → A: 통화별로 동시에 하나의 수집 작업만 허용하고, 중복 요청은 진행 중인 작업의 완료를 함께 기다린다
- Q: 수집 실패 기록을 사후에 조회할 수 있어야 하는가? → A: 수집 작업 기록(시작·종료 시각, 대상 구간, 결과, 실패 사유)을 영속 저장하고 화면에서 최근 이력을 조회한다
- Q: 출처가 과거 환율을 정정 발표했을 때 기존 저장값을 어떻게 하는가? → A: 최신 값으로 덮어쓰고, 이전 값은 원본 응답 기록으로 추적 가능하게 보존한다
- Q: 차트 요청 구간에 미수집 구간이 있으면 자동 수집을 유발하는가? → A: 조회와 동일한 자동 수집 규칙(FR-035 임계값)을 차트에도 적용한다
- Q: 외부 응답 원본을 얼마나 보관하는가? → A: 모든 응답 원본을 기한 없이 영구 보관한다
- Q: 수집 작업 이력을 얼마나 오래 보관하는가? → A: 실패·부분 성공 이력은 영구 보관, 성공 이력은 설정된 기간(기본 90일)만 보관

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 특정 날짜의 환율 조회 (Priority: P1)

투자 판단을 위해 과거 특정 시점의 환율을 확인하려는 사용자가, 통화(USD/JPY/EUR)와 날짜를
선택하면 그날의 원화 매매기준율을 즉시 확인한다. 해당 날짜의 데이터가 아직 축적되지 않았다면
시스템이 부족한 구간을 자동으로 채운 뒤 결과를 제시한다.

**Why this priority**: 이 기능의 존재 이유 그 자체다. 축적·조회가 동작하지 않으면 나머지
기능(스프레드, 차트)은 표시할 대상이 없다. 이 스토리만 구현해도 "과거 환율을 찾아보는" 완결된
가치를 제공한다.

**Independent Test**: 데이터가 비어 있는 상태에서 특정 통화와 과거 날짜를 지정해 조회했을 때,
시스템이 데이터를 수집하고 그 날짜의 매매기준율을 반환하는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 해당 날짜의 환율이 이미 축적되어 있을 때, **When** 사용자가 통화와 날짜를 선택하면,
   **Then** 그 날짜의 매매기준율과 값의 단위, 데이터 출처가 함께 표시된다.
2. **Given** 저장된 마지막 날짜가 조회하려는 날짜보다 이전일 때, **When** 사용자가 그 날짜를 조회하면,
   **Then** 시스템이 마지막 저장 날짜의 다음날부터 어제까지를 수집해 저장한 뒤 결과를 표시한다.
3. **Given** 데이터가 하나도 없을 때, **When** 사용자가 임의의 과거 날짜를 조회하면,
   **Then** 시스템이 필요한 구간을 수집하고 결과를 표시한다. 수집할 구간이 길어(기본 30일 초과,
   FR-035b) 오래 걸리는 경우에는 결과를 기다리게 하지 않고 수집이 진행 중임을 알린다
   (진행률 표시는 User Story 4).
4. **Given** 선택한 날짜가 환율 고시가 없는 날(주말·공휴일)일 때, **When** 사용자가 조회하면,
   **Then** 시스템은 고시가 없다는 사실을 주 결과로 알리고, 직전 영업일의 값과 날짜를
   구분된 참고 정보로 함께 제시한다.
5. **Given** 선택한 날짜가 **해당 통화의** 축적 시작일 이전이거나 미래일 때, **When** 사용자가 조회하면,
   **Then** 시스템은 조회 가능한 범위를 알리고 값을 반환하지 않는다.

### User Story 2 - 스프레드를 반영한 실거래 환율 확인 (Priority: P2)

사용자는 매매기준율만으로는 실제 부담 비용을 알 수 없다. 통화별 스프레드를 설정하면 조회 결과에
현금 살 때 / 현금 팔 때 / 송금 보낼 때 / 송금 받을 때 4종 파생 환율이 함께 표시된다.

**Why this priority**: 매매기준율은 실제 거래 가격이 아니다. 실제 투자 판단에 쓰려면 스프레드가
반영되어야 한다. 다만 조회(US1)가 동작한 뒤에야 의미가 있으므로 P2다.

**Independent Test**: 알려진 매매기준율과 스프레드 값을 입력했을 때 4종 파생 환율이 정확히 계산되는지,
스프레드를 변경하면 결과가 즉시 반영되는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 통화별 스프레드가 설정되어 있을 때, **When** 사용자가 특정 날짜의 환율을 조회하면,
   **Then** 매매기준율과 함께 4종 파생 환율이 표시되고 각 값에 적용된 스프레드가 함께 드러난다.
2. **Given** 조회 결과가 표시된 상태에서, **When** 사용자가 해당 통화의 스프레드 값을 변경하면,
   **Then** 파생 환율이 변경된 스프레드 기준으로 다시 계산되어 표시된다.
3. **Given** 스프레드를 한 번도 설정하지 않았을 때, **When** 사용자가 조회하면,
   **Then** 통화별 기본 스프레드가 적용된 결과가 표시된다.
4. **Given** 사용자가 스프레드에 음수나 1 이상의 값을 입력할 때, **When** 저장을 시도하면,
   **Then** 시스템은 허용 범위를 벗어났음을 알리고 기존 값을 유지한다.

### User Story 3 - 기간별 환율 추이 시각화 (Priority: P2)

사용자가 통화와 기간을 선택하면 그 구간의 환율 추이를 차트로 확인하고, 차트 위의 특정 시점을
가리켜 그날의 값을 확인하거나 상세 조회로 이동한다.

**Why this priority**: 단일 날짜 조회만으로는 "언제가 유리했는가"를 판단할 수 없다. 추이를 봐야
투자 시점 비교가 가능하다. 조회 기반이 갖춰진 뒤 붙는 기능이므로 P2다.

**Independent Test**: 축적된 구간을 지정해 차트를 요청했을 때 해당 구간의 값이 시간 순으로
표시되고, 임의 시점을 가리켰을 때 그 날짜와 값이 정확히 나타나는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 특정 구간의 환율이 축적되어 있을 때, **When** 사용자가 통화와 기간을 선택하면,
   **Then** 그 구간의 환율 추이가 시간 순 차트로 표시된다.
2. **Given** 차트가 표시된 상태에서, **When** 사용자가 차트의 특정 시점을 가리키면,
   **Then** 그 시점의 날짜와 환율 값이 표시된다.
3. **Given** 차트의 특정 시점이 선택되었을 때, **When** 사용자가 상세 보기를 요청하면,
   **Then** 해당 날짜의 상세 조회 결과로 이동한다.
4. **Given** 표시 구간 안에 아직 수집되지 않은 구간이 있을 때, **When** 사용자가 차트를 요청하면,
   **Then** 시스템은 날짜 조회와 동일한 자동 수집 규칙을 적용해 그 구간을 채운 뒤 차트를 표시한다.
5. **Given** 수집이 완료된 뒤에도 고시가 없어 값이 없는 날이 남아 있을 때, **When** 차트가 렌더링되면,
   **Then** 시스템은 없는 값을 만들어 이어 붙이지 않고 그 구간이 비어 있음을 알아볼 수 있게 표현한다.
6. **Given** 사용자가 축적된 전 구간(30년 이상)을 선택할 때, **When** 차트가 렌더링되면,
   **Then** 조작(확대·이동·값 확인)이 지연 없이 이루어진다.

---

### User Story 4 - 대량 수집의 진행 확인과 중단 후 재개 (Priority: P3)

30년치 전 구간을 처음 수집하는 작업은 오래 걸린다. 사용자는 그 진행 상황을 실시간으로 확인하고,
작업이 중단되어도 다시 실행하면 중단 지점부터 이어진다는 것을 확인한다.

**Why this priority**: 없어도 데이터는 수집되지만, 진행 상황이 보이지 않으면 사용자는 멈춘 것으로
판단하고 중복 실행하거나 포기한다. 축적 기능이 동작한 뒤에 붙는 신뢰성·가시성 기능이므로 P3다.

**Independent Test**: 대량 수집을 시작한 뒤 진행률이 갱신되는지, 강제로 중단한 뒤 재실행했을 때
이미 수집된 구간을 다시 받지 않고 이어서 진행하는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 전 구간 수집이 진행 중일 때, **When** 사용자가 화면을 보고 있으면,
   **Then** 현재 처리 중인 통화, 완료된 구간, 남은 구간이 새로고침 없이 갱신된다.
2. **Given** 수집이 중간에 중단되었을 때, **When** 사용자가 다시 수집을 실행하면,
   **Then** 이미 수집된 구간은 다시 요청하지 않고 마지막 완료 지점의 다음 구간부터 진행한다.
3. **Given** 데이터 제공처의 호출 한도를 소진했을 때, **When** 수집이 계속 실패하면,
   **Then** 시스템은 수집을 중단하고 그 사유를 사용자에게 알리며, 이미 저장된 데이터는 그대로 유효하다.
4. **Given** 수집이 어느 구간까지 완료되었는지 확인하고 싶을 때, **When** 사용자가 수집 현황을 조회하면,
   **Then** 통화별로 수집된 구간과 마지막 갱신 시각이 표시된다.

---

### Edge Cases

- 조회 날짜가 주말·공휴일 등 환율 고시가 없는 날일 때 어떻게 응답하는가?
- 조회 날짜가 해당 통화의 수집 완료 구간 시작 이전이거나 미래 날짜일 때 어떻게 응답하는가?
- 오늘 날짜를 조회할 때, 당일 고시가 아직 확정되지 않은 상태를 어떻게 다루는가?
- 데이터 제공처가 오류를 정상 응답처럼 반환할 때 이를 성공으로 오인하지 않는가?
- 데이터 제공처의 일일 호출 한도를 소진했을 때 이미 저장된 데이터는 유지되는가?
- 데이터 제공처의 통화 식별 체계가 변경되었을 때 잘못된 통화의 값을 저장하지 않는가?
- 이미 저장된 날짜의 값이 출처에서 정정되었을 때, 갱신 전 값을 추적할 수 있는가?
- 동일 구간에 대한 수집이 중복 실행되었을 때 같은 날짜의 레코드가 두 번 저장되지 않는가?
- 한 통화의 수집이 진행 중인데 같은 통화에 대한 조회가 또 수집을 유발하면 어떻게 되는가?
- 한 통화의 대량 수집이 진행 중일 때 다른 통화의 조회가 차단되지는 않는가?
- 통화마다 고시 단위가 다를 때(예: 일부 통화는 100단위 기준) 값의 의미가 뒤섞이지 않는가?
- 차트 요청 구간이 축적 범위를 벗어날 때 어떻게 표현하는가?
- 데이터가 전혀 없는 상태에서 차트의 "전체" 기간을 선택하면 어떻게 되는가?
- 스프레드가 0일 때 파생 환율 4종이 모두 매매기준율과 같아지는가?

## Requirements *(mandatory)*

### Functional Requirements

**축적**

- **FR-001**: 시스템은 USD, JPY, EUR의 일별 원화 매매기준율을 외부 데이터 제공처로부터 수집하여
  영속 저장해야 한다.
- **FR-002**: 시스템은 **통화별로 데이터 제공처가 실제로 제공하는 최초 고시일**부터 어제까지를
  축적 대상 범위로 삼아야 한다. 통화마다 시작일이 다르다.

  | 통화 | 최초 제공일 | 비고 |
  |------|-------------|------|
  | USD | 1964-05-04 | |
  | JPY | 1977-04-01 | |
  | EUR | 1994-04-11 | 유로 도입(1999-01-01) 이전 구간은 출처가 이전 통화 단위를 이어 붙인 것으로 보인다 |

  위 값은 2026-08-30 실측으로 확인했으며, 각 통화의 직전 연도에 데이터가 없음을 함께 확인했다.
- **FR-002a**: 시스템은 각 통화의 실제 최초 제공일을 수집 중 발견해 기록하고 사용자에게
  노출해야 한다. FR-002 표의 값은 탐색 시작점일 뿐이며, 출처가 제공 범위를 바꾸면 그 사실이
  반영되어야 한다.
- **FR-003**: 시스템은 동일 구간을 여러 번 수집해도 같은 통화·날짜의 레코드를 중복 저장하지 않아야 한다.
- **FR-003a**: 이미 저장된 통화·날짜에 대해 출처가 이전과 다른 값을 제공하면, 시스템은 저장된 값을
  최신 값으로 갱신하고 갱신 시각을 기록해야 한다.
- **FR-003b**: 값이 갱신되더라도 이전에 수신한 원본 응답 기록은 삭제되거나 덮어써지지 않아야 하며,
  갱신 전 값을 사후에 추적할 수 있어야 한다.
- **FR-004**: 시스템은 저장된 각 환율 레코드에 대해 데이터 출처와 수집 시각을 함께 기록해야 한다.
- **FR-004a**: 시스템은 외부 데이터 제공처로부터 수신한 응답 원본을 정규화된 시계열과 분리하여
  저장하고 기한 없이 보관해야 한다. 오래된 원본을 자동으로 정리해서는 안 된다.
- **FR-004b**: 각 원본 응답 기록에는 수신 시각과 요청 대상 통화·날짜 구간이 함께 기록되어야 한다.
- **FR-005**: 시스템은 통화별로 수집이 완료된 날짜 구간을 기록하고 조회할 수 있어야 한다.
- **FR-006**: 시스템은 수집 완료 구간과 "고시가 없어서 값이 없는 날"을 구분할 수 있어야 하며,
  후자를 미수집 상태로 오인해 반복 요청하지 않아야 한다.
- **FR-007**: 시스템은 통화별 고시 단위(예: 100단위 기준 통화)를 값과 함께 기록하여
  단위가 다른 통화의 값이 동일 기준으로 오인되지 않도록 해야 한다.

**수집 작업의 안정성**

- **FR-008**: 시스템은 전체 수집 구간을 더 작은 구간으로 나누어 순차적으로 요청해야 하며,
  전 구간을 한 번의 요청으로 가져오지 않아야 한다.
- **FR-009**: 구간 크기, 요청 간 최소 대기 시간, 동시 요청 수, **통화별 탐색 시작일**은 운영자가
  조정 가능한 설정값이어야 하며, 변경에 코드 수정이 필요해서는 안 된다.
- **FR-010**: 시스템은 각 구간의 수집이 성공할 때마다 그 결과를 저장하고 수집 완료 범위를 갱신해야 한다.
- **FR-011**: 수집 작업이 중단되면, 재실행 시 이미 완료된 구간을 다시 요청하지 않고
  마지막 완료 지점의 다음 구간부터 이어가야 한다.
- **FR-012**: 시스템은 일시적 실패에 대해 재시도하되, 재시도 간격을 점진적으로 늘려야 한다.
- **FR-013**: 데이터 제공처의 호출 한도 소진이 지속되면 시스템은 수집 작업을 중단하고 그 사유를
  사용자에게 알려야 하며, 이미 저장된 데이터는 유효한 상태로 유지해야 한다.
- **FR-014**: 시스템은 데이터 제공처가 오류를 정상 응답 형태로 반환하는 경우에도 이를 오류로
  판별해야 하며, 오류 응답을 유효한 데이터로 저장해서는 안 된다.
- **FR-015**: 시스템은 데이터 제공처의 통화 식별 체계가 변경되었을 때 이를 감지하고,
  잘못된 통화의 값을 저장하지 않아야 한다.
- **FR-015a**: 시스템은 동일 통화에 대해 동시에 두 개 이상의 수집 작업을 실행해서는 안 된다.
- **FR-015b**: 이미 수집이 진행 중인 통화에 대해 수집이 다시 요청되면, 시스템은 새 작업을
  생성하지 않고 진행 중인 작업의 완료를 기다려 그 결과를 사용해야 한다.
- **FR-015c**: 서로 다른 통화의 수집 작업은 서로를 차단하지 않고 동시에 실행될 수 있어야 한다.

**조회**

- **FR-016**: 사용자는 통화와 날짜를 지정하여 해당일의 매매기준율을 조회할 수 있어야 한다.
- **FR-017**: 조회 대상 날짜가 수집 범위 밖이면, 시스템은 마지막 수집 날짜의 다음날부터
  어제까지를 수집한 뒤 결과를 제시해야 한다.
- **FR-018**: 조회 대상 날짜에 고시가 없으면 시스템은 해당일에 고시가 없다는 사실을 주 결과로
  제시해야 하며, 보간하거나 인접일 값으로 대체한 값을 그날의 값으로 반환해서는 안 된다.
- **FR-018a**: 시스템은 고시가 없는 날의 조회 결과에 직전 영업일의 값과 그 날짜를,
  주 결과와 시각적으로 구분되는 별도의 참고 정보로 함께 제시해야 한다.
- **FR-018b**: 참고로 제시된 직전 영업일 값은 조회 요청일의 값이 아님이 표기상 드러나야 한다.
- **FR-019**: 조회 대상 날짜가 **해당 통화의 수집 완료 구간 시작** 이전이거나 오늘 이후이면,
  시스템은 조회 가능한 범위를 알리고 값을 반환하지 않아야 한다.
- **FR-020**: 조회 결과에는 값, 통화, 날짜, 고시 단위, 데이터 출처가 포함되어야 한다.

**스프레드와 파생 환율**

- **FR-021**: 사용자는 통화별로 4종 스프레드(현금 살 때 / 현금 팔 때 / 송금 보낼 때 / 송금 받을 때)를
  설정할 수 있어야 한다.
- **FR-022**: 시스템은 조회 결과에 매매기준율과 함께 4종 파생 환율을 제시해야 한다.
- **FR-023**: 파생 환율은 매입 방향(현금 살 때, 송금 보낼 때)에 대해 매매기준율에 스프레드 비율만큼
  가산하고, 매도 방향(현금 팔 때, 송금 받을 때)에 대해 같은 비율만큼 차감하여 산출해야 한다.
- **FR-024**: 시스템은 스프레드를 설정하지 않은 통화에 대해 정해진 기본 스프레드를 적용해야 한다.
- **FR-025**: 시스템은 허용 범위를 벗어난 스프레드 값 입력을 거부하고 기존 값을 유지해야 한다.
- **FR-026**: 시스템은 현재 설정된 스프레드를 모든 과거 날짜에 동일하게 적용해야 한다.
  시점별 스프레드 이력은 관리하지 않는다.
- **FR-026a**: 조회 결과에는 산출에 사용된 스프레드 값이 함께 포함되어야 하며, 결과가 "현재 스프레드
  조건을 과거 시점에 적용한 가정 비교"임이 사용자에게 드러나야 한다.
- **FR-027**: 동일한 매매기준율과 동일한 스프레드 입력에 대해 파생 환율 산출 결과는 항상 동일해야 한다.

**시각화**

- **FR-028**: 사용자는 통화와 기간을 지정하여 해당 구간의 환율 추이를 차트로 확인할 수 있어야 한다.
- **FR-029**: 사용자는 차트의 조회 기간을 미리 정의된 프리셋과 직접 지정 두 방식으로 선택할 수 있어야 한다.
- **FR-030**: 사용자는 차트의 특정 시점을 가리켜 그 날짜와 값을 확인할 수 있어야 한다.
- **FR-031**: 사용자는 차트에서 선택한 시점의 상세 조회 결과로 이동할 수 있어야 한다.
- **FR-032**: 차트는 표시 구간 내의 미수집 구간과 고시 없는 날에 대해 값을 만들어 이어 붙이지 않고,
  해당 구간이 비어 있음을 알아볼 수 있게 표현해야 한다.
- **FR-032a**: 차트 요청 구간에 미수집 구간이 포함되어 있으면, 시스템은 날짜 조회와 동일한
  자동 수집 규칙(FR-035, FR-035a, FR-035b)을 적용해야 한다.
- **FR-032b**: 자동 수집이 완료된 뒤에도 값이 존재하지 않는 날(고시 없음)에 대해서는
  FR-032에 따라 비어 있음으로 표현해야 한다.
- **FR-033**: 차트는 축적된 전 구간(최장 통화 기준 16,000건 이상)을 표시할 때도 조작 응답성을
  유지해야 한다.

**진행 상황 가시화**

- **FR-034**: 시스템은 진행 중인 수집 작업의 현재 통화, 완료 구간, 남은 구간, 최근 오류를
  사용자 화면에 새로고침 없이 갱신하여 제시해야 한다.
- **FR-035**: 조회 요청이 수집을 유발할 때, 필요한 구간의 길이가 설정된 임계값 이하이면
  시스템은 수집 완료까지 대기한 뒤 조회 결과를 제시해야 한다.
- **FR-035a**: 필요한 구간의 길이가 임계값을 초과하면, 시스템은 즉시 진행 상태를 제시하고
  수집이 완료된 후 조회 결과를 갱신해야 한다.
- **FR-035b**: 대기와 백그라운드 처리를 가르는 임계값은 운영자가 조정 가능한 설정값이어야 하며,
  기본값은 30일로 한다.
- **FR-036**: 시스템은 각 수집 작업에 대해 시작 시각, 종료 시각, 대상 통화와 날짜 구간,
  결과(성공/부분 성공/실패), 실패 사유를 영속 저장해야 한다.
- **FR-037**: 사용자는 최근 수집 작업 이력을 조회하여 각 작업의 대상 구간과 결과, 실패 사유를
  확인할 수 있어야 한다.
- **FR-038**: 실패한 수집 작업의 기록은 이후의 성공한 작업에 의해 삭제되거나 덮어써지지 않아야 한다.
- **FR-038a**: 실패 또는 부분 성공으로 종료된 수집 작업 이력은 기한 없이 보관해야 한다.
- **FR-038b**: 성공으로 종료된 수집 작업 이력은 설정된 보관 기간이 지나면 정리할 수 있다.
  보관 기간은 운영자가 조정 가능한 설정값이어야 하며 기본값은 90일로 한다.

### Key Entities

- **환율 시계열 레코드**: 하나의 통화가 특정 날짜에 가졌던 매매기준율. 통화, 날짜, 값, 고시 단위,
  데이터 출처, 수집 시각, 마지막 갱신 시각을 가진다. 통화와 날짜의 조합으로 유일하게 식별되며,
  출처의 정정 발표 시 값이 갱신될 수 있다.
- **통화**: 축적 대상이 되는 외화. 식별 코드(USD/JPY/EUR), 표시 이름, 고시 단위 기준을 가진다.
- **스프레드 설정**: 통화별로 4종 거래 유형(현금 매입/매도, 송금 송금/수취)에 적용할 비율.
- **수집 커버리지**: 통화별로 어느 날짜 구간까지 수집이 완료되었는지에 대한 기록.
  마지막 수집 날짜와 마지막 갱신 시각을 가진다.
- **수집 작업**: 한 번의 축적 실행 단위. 대상 통화와 날짜 구간, 시작·종료 시각, 진행 상태,
  완료된 구간, 결과, 실패 사유를 가진다. 하나의 통화에 대해 진행 중인 작업은 동시에 하나만
  존재할 수 있다. 실패·부분 성공 이력은 영구 보존되고, 성공 이력은 보관 기간 경과 후 정리된다.
- **원본 응답 기록**: 데이터 제공처로부터 받은 응답의 원형. 수신 시각과 요청 대상 통화·날짜 구간을
  함께 가진다. 정규화된 시계열과 분리되어 기한 없이 보관되며, 값의 출처와 갱신 전 값을 사후에
  추적하는 근거가 된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 통화와 날짜를 선택한 시점부터 3초 이내에 해당일 환율을 확인한다
  (해당 구간이 이미 수집된 경우).
- **SC-002**: 각 통화의 최초 제공일부터 현재까지 USD, JPY, EUR 3개 통화의 고시일 기준 환율을 누락 없이
  수집하며, 수집률은 데이터 제공처가 제공하는 고시일 대비 100%다.
- **SC-003**: 출처의 정정 발표가 없는 한, 동일한 날짜·통화를 반복 조회했을 때 항상 동일한 값이
  반환된다(재현성 100%). 정정으로 값이 갱신된 경우에도 갱신 전 값을 원본 응답 기록에서 100% 추적할 수 있다.
- **SC-004**: 수집 작업이 임의 시점에 중단된 뒤 재실행했을 때, 이미 수집된 구간을 다시 요청하는
  비율이 0%이며 최종 데이터에 중복 레코드가 발생하지 않는다.
- **SC-005**: 데이터 제공처의 호출 한도를 초과하지 않고 전 구간 최초 수집을 완료한다
  (한도 초과로 인한 작업 실패 0회).
- **SC-006**: 사용자는 축적된 전 구간(최장 62년) 차트에서 확대·이동·값 확인 조작 시 1초 이내에
  화면 반응을 받는다.
- **SC-007**: 고시가 없는 날을 조회했을 때, 시스템이 임의로 만들어낸 값을 반환하는 사례가 0건이다.
- **SC-008**: 사용자는 스프레드를 변경한 뒤 2초 이내에 갱신된 파생 환율을 확인한다.
- **SC-009**: 대량 수집 작업 중 사용자는 진행 상황이 갱신되지 않는 구간을 10초 이상 경험하지 않는다.
- **SC-010**: 동일 통화에 대해 동시에 실행되는 수집 작업의 수는 항상 1 이하이며, 중복 요청으로 인한
  외부 데이터 제공처 추가 호출은 0건이다.
- **SC-011**: 실패한 수집 작업의 100%에 대해 사용자가 별도 도구 없이 화면에서 실패 사유와
  대상 구간을 사후 확인할 수 있다.

| 용어 | 뜻 | 어디에 있나 |
|------|-----|-------------|
| **탐색 시작일** | 수집을 시작해 볼 지점. 운영자가 조정하는 설정값 | `ECOS_PROBE_START_*` (FR-009) |
| **최초 제공일** | 출처가 실제로 값을 주는 첫 날. 수집 중 발견한다 | `currency.first_available_date` (FR-002a) |
| **수집 완료 구간 시작** | 실제로 수집을 마친 구간의 시작. 조회 가능 하한 | `fx_coverage.covered_from` (FR-019) |

탐색 시작일 ≤ 최초 제공일이 정상이다. 탐색 시작일이 최초 제공일보다 늦으면 그 차이만큼
데이터가 조용히 잘린다 — 잘린 구간은 오류를 내지 않으므로 드러나지 않는다.

## Assumptions

명세에 명시되지 않은 부분에 대해 아래 기본값을 선택했다. `/speckit-clarify` 단계에서 뒤집을 수 있다.

- **데이터 출처**: 원화 매매기준율의 단일 기준 출처로 한국은행 ECOS를 사용한다. 다른 출처와의
  교차 검증은 이번 범위에 포함하지 않는다.
- **축적 단위**: 일별 데이터만 수집한다. 주별·월별 집계는 필요 시 일별 데이터로부터 파생한다.
- **오늘 데이터**: 당일 고시는 확정 전 변경될 수 있으므로 수집 대상에서 제외하고, 축적 범위의
  끝을 어제로 둔다. 사용자 요청의 "오늘을 제외한" 조건을 그대로 반영한 것이다.
- **수집 완료 기록**: 고시가 없는 날(주말·공휴일)을 매번 재요청하지 않기 위해, 값 존재 여부와
  별개로 "어느 구간까지 수집을 시도해 완료했는지"를 기록한다.
- **고시 단위**: 100단위로 고시되는 통화(JPY)는 제공처가 고시한 형태 그대로 저장하고 단위를
  함께 기록한다. 표시 단계에서 사용자가 오인하지 않도록 단위를 함께 노출한다. 저장 시점에
  1단위로 환산하지 않는 이유는 원본 값의 의미를 보존하기 위해서다.
- **파생 환율 저장**: 파생 환율은 저장하지 않고 조회 시점에 매매기준율과 스프레드로 산출한다.
  스프레드가 변경 가능하므로 미리 계산해 저장하면 값이 즉시 무효가 되기 때문이다.
- **반올림**: 파생 환율은 소수점 둘째 자리까지, 사사오입(반올림)으로 산출한다. 재현성을 위해
  자릿수와 방식을 고정한다.
- **스프레드 적용 범위**: 사용자 계정 개념이 없으므로 스프레드 설정은 시스템 전역에 하나씩,
  통화별로 관리한다.
- **스프레드 허용 범위**: 0 이상 1 미만의 비율만 허용한다.
- **기본 스프레드**: USD는 현금 0.0018 / 송금 0.0005, JPY와 EUR은 현금 0.0020 / 송금 0.0006을
  초기값으로 사용한다.
- **차트 표시 대상**: 한 번에 한 통화의 매매기준율을 표시한다. 복수 통화 동시 비교와 파생 환율
  동시 표시는 이번 범위에서 제외한다(통화별 고시 단위가 달라 축 기준을 별도로 정해야 하며,
  이는 다음 반복에서 다룬다).
- **차트 기간 프리셋**: 1개월, 1년, 5년, 전체를 제공한다.
- **축적 시작일**: 통화별로 다르다(FR-002 표). 출처가 제공 범위를 바꿀 수 있으므로 그 값을
  탐색 시작점으로만 쓰고, 실제 최초 제공일은 수집 중 발견해 기록한다(FR-002a).
  헌법 v4.1.0이 FX 기준 시작일을 "통화별 출처 제공 최초일"로 규정하며, 특정 날짜를
  코드나 스키마에 하드코딩하는 것을 금지한다.
- **동시 사용자**: 개인 사용 규모를 전제한다. 다중 사용자 동시 접속 부하는 이번 범위 밖이다.

## Dependencies

- 한국은행 ECOS의 환율 통계 조회 서비스 가용성과 발급된 인증 수단.
  인증 수단은 저장소에 포함하지 않고 실행 환경에서 주입한다.
- 데이터 제공처의 호출 한도 정책. 수집 작업의 구간 크기와 대기 시간 기본값은 이 한도에 따라 정한다.
  실제 한도 수치는 계획 단계에서 확인이 필요하다(`research-inputs/ecos-api-notes.md` 참조).

## Out of Scope

- USD/JPY/EUR 외의 통화
- 일별 외 주기(주별·월별)의 직접 수집
- 다른 자산군(가상자산·주식·예금·부동산)과의 비교 시뮬레이션
- 환율 기반 수익률·복리 계산
- 사용자 인증 및 사용자별 설정 분리
- 차트 이미지 내보내기, 주석·드로잉 도구
- 복수 통화 동시 차트 비교
