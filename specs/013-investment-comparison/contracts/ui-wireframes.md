# 화면 계약 (013)

**Date**: 2026-10-08 | **Data Model**: [../data-model.md](../data-model.md) | **REST**: [rest-api.md](./rest-api.md)

화면은 `src/app/compare/page.tsx` 하나다. 상태는 `stores/compareStore.ts`(data-model 5). 금액·비율 글자는 메뉴와 같은 형식 함수(`lib/format.ts`)로 보인다.

## F2. 자산군과 대상 고르기 (US1 — FR-002·FR-003·FR-004)

```
투자 비교
┌ 자산군 ─────────────────────────────────────────────────────────────┐
│ (●) 주식  ( ) 가상자산  ( ) 예금  ( ) 부동산                           │
└─────────────────────────────────────────────────────────────────────┘
┌ 비교 대상 (3/10) ───────────────────────────────────────────────────┐
│ [ 종목 검색 — 국내·미국, 한글·초성·코드            ]                   │
│ [삼성전자 ×] [SK하이닉스 ×] [XLK ×]                                   │
│ ⓘ 최대 10개 · 2개 이상이어야 실행할 수 있습니다                         │
└─────────────────────────────────────────────────────────────────────┘
```

- 자산군 라디오를 바꾸면 대상·결과를 비운다(시작일·금액은 남는다). 진행 구독을 모두 푼다
- 대상 칩: 이름(주식·가상자산은 메뉴처럼 외부 링크 — `lib/externalLinks`) + 빼기 단추(`aria-label="{이름} 빼기"`). 칩 차례 = 더한 차례
- 11번째: 더하지 않고 `role="alert"` "최대 10개까지 비교할 수 있습니다"
- 같은 대상: 더하지 않고 "이미 더한 대상입니다"
- 자산군별 고르기:

| 자산군 | 부품 | 더하는 때 |
|--------|------|-----------|
| 주식 | `StockSearch` → 등록(`lib/stockSelection.registerStock`) | 등록 응답이 오면. 등록 중 "종목을 등록하는 중…", 실패는 문구 |
| 가상자산 | `CoinSearch`(목록 진행 스트림 포함) | 고르면 곧바로 |
| 예금 | `InstitutionChecklist` — 체크박스 다섯(정기 적금이면 적금 없는 곳은 꺼짐 + 까닭) | 체크 = 더함, 해제 = 뺌. 최대 5 |
| 부동산 | `RegionPicker` → `ComplexPicker` → `AreaBucketPicker`(비교 전용 인스턴스) + "더하기" 단추 | 평형까지 고르고 "더하기". 고르기는 이어서 다른 단지를 고를 수 있게 남는다 |

## F3. 공통 조건 (FR-005~FR-009)

```
┌ 공통 조건 ──────────────────────────────────────────────────────────┐
│ 투자 방식  (●) 일시금  ( ) 적립식  [매달 ▾]                            │
│ 시작일     [2020-01-02] « ‹ › »                                     │
│ 투자 원금  [10,000,000]  [KRW ▾]   ☑ 배당 재투자                      │
│                                                [ 비교 실행 ]         │
└─────────────────────────────────────────────────────────────────────┘
```

- 방식: 주식·가상자산 `InvestmentModeFields`(일시금·적립식 + 주기), 예금 `ProductPicker`(정기예금·정기 적금), 부동산 "매입 후 보유"(고정 글자)
- 시작일: `StartDateInput` 하나(상한은 자산군의 메뉴와 같다 — 주식 `localYesterday`, 가상자산 `utcYesterday`, 예금·부동산 `kstToday`). 부동산은 라벨 "매입일"
- 금액 라벨: 일시금 "투자 원금", 적립식 "한 번 납입액"(`amountLabel`), 정기 적금 "월 납입액". 부동산은 금액 칸이 없고 "매입가는 대상마다 그 달 시세" 안내
- 통화: 원화 + 모든 대상의 통화가 같을 때 그 통화. 고를 수 없게 된 통화가 골라져 있으면 원화로 돌리고 알린다. 예금·부동산은 통화 칸 없음
- 배당 재투자: 주식만
- "비교 실행": 대상 2개 미만이면 꺼짐 + "2개 이상이 필요합니다"

## F4. 실행 중·막힘 (FR-010·FR-013·FR-014)

**막힘** — 결과 자리 대신:

```
┌ ⚠ 비교할 수 없습니다 ─────────────────────────────────────────────────┐
│ • SK스퀘어 — 상장 전 (2021-11-29부터)                                  │
│ • 저축은행 — 정기 적금이 없는 투자처 · 이 대상을 빼세요                  │
│ 모든 대상이 가능한 가장 이른 시작일: 2021-11-29  [ 시작일 옮기기 ]        │
└─────────────────────────────────────────────────────────────────────┘
```

- `role="alert"`. 대상마다 이름 + 까닭(research R13-6 표의 문구). 시작일로 안 풀리는 까닭에는 "이 대상을 빼세요"(부동산 시세 없음은 "매입일을 바꾸거나 이 대상을 빼세요").
  시작일이 너무 늦으면 "시작일을 2026-10-07 이전으로 바꾸세요"(제안 줄에 들지 않는다)
- 제안 줄은 시작일로 풀리는 대상이 있고 **수집 중인 대상이 없을 때만**. 수집 중이면 "수집 중인 대상 N개 — 끝나면 제안 날짜를 정합니다"
- "시작일 옮기기"는 시작일만 바꾼다(실행하지 않는다)

**수집 중·실패** — 결과는 계산된 대상부터 보이고(F5), 계산되지 않은 대상은 표의 줄로 남는다:

| 줄 | 값 칸 | 이름 칸 아래 |
|----|-------|--------------|
| 수집 중 | 모두 비움(0이 아니다) | "수집 중 · 2015-03 ~ 2020-01 받는 중" + 진행 막대(스냅숏) |
| 수집 실패 | 모두 비움 | "수집 실패 — {까닭}" + "다시 시도" 단추 |

- 수집 중·실패 줄은 정렬과 무관하게 맨 아래다. 그래프에는 없다

## F5. 비교 표 (FR-011·FR-011a·FR-011b·FR-012·FR-014)

> 아래 그림은 처음(US1)의 열 7개다. 지금 열 차례는 반복 문단들이 정한다 — 대상, 기준일, 투자 원금, 시작일 단가, 기준일 단가, 등락, 현재 가치, 비용, 투자 수익, 수익률,
> 투자 시뮬레이션(반복 2026-10-09·2026-10-09b)

```
기준 통화 KRW · 열 머리를 눌러 정렬
┌──────────────┬──────────┬──────────────┬──────────────┬──────────────┬──────────────┬──────────┐
│ 대상          │ 기준일    │ 투자 원금 ▾   │ 현재 가치     │ 비용          │ 투자 수익     │ 수익률    │
├──────────────┼──────────┼──────────────┼──────────────┼──────────────┼──────────────┼──────────┤
│ XLK          │ 10-06    │ ₩20,000,000  │ ₩539,297,203 │ -₩113,030,970│ ₩409,114,677 │ +2045.57%│
│  USD · 1,358.50(10-06 ECOS)            │              │ 반영 ₩2,848,444│ 매도 후       │          │
│              │          │              │              │ 매도 ₩110,182,526│            │          │
│ 삼성전자      │ 10-07    │ ₩20,000,000  │ ...          │ ...          │ ... 매도 후   │ ...      │
│ SK하이닉스 ⏳ │ —        │ —            │ —            │ —            │ —            │ —        │
│  수집 중 · 2001-01 ~ 2020-01 받는 중 ▓▓▓░░                                                       │
└──────────────┴──────────┴──────────────┴──────────────┴──────────────┴──────────────┴──────────┘
```

- 열: 대상, 기준일, 투자 원금, 현재 가치, 비용, 투자 수익, 수익률(FR-011). 머리 단추로 정렬(오름·내림 번갈아, `aria-sort`) — `lib/decimalOrder.compareDecimal`, `null`은 끝.
  처음 차례는 더한 차례
- **투자 원금**: 원화 원금이면 원화 하나, 외화 원금이면 "$10,000 (₩13,581,000)". 적립식은 총 납입 원금 + "N회 납입", 부동산은 투입 금액 + "매입가 ₩… · 취득 비용 포함"
- **비용**: 합(`-₩…`) + 두 줄 "반영 ₩…"·"매도 가정 ₩…". 펼침(ⓘ)으로 항목(`kind` → 글자: 매수 수수료, 배당 소득세, 만기 이자 소득세, 경과 이자 소득세, 취득세…). 부동산
  취득 비용 항목엔 "투자 원금에 포함". 칸 도움말: "반영 몫은 현재 가치(또는 투자 원금)에 이미 들어 있습니다 — 현재 가치 − 비용 − 투자 원금은 투자 수익과 다릅니다"
  (FR-011 실패 양상). 비운 항목은 "—"와 까닭("과세 시행일 뒤 — 세법 표 밖")
- **투자 수익·수익률**: 주 값 + 기준 글자("매도 후" / "보유 중" / 값 없으면 "—"). 표 머리 아래 안내: "매도 비용을 빼는 자산군은 기준일에 판다고 가정한 값입니다"
- **잠정**(원칙 V): `comparison.provisional`이 있으면 기준일 칸에 ⏳ + 까닭(미발표 달 금리 / 잠정 시세 / 추정 시세 / 기준일이 계산 끝 전)
- **환율**(원칙 V): 외화 대상은 이름 아래 "USD · 1,358.50(10-06 ECOS 매매기준율)"
- 이름 칸은 메뉴처럼 외부 링크. 표 파일은 `tests/compareNoClientFinance.test.ts`가 본다(R13-11)
- **반복 2026-10-09 — 단가 열 셋**(spec FR-011a, data-model 3.2 — 아래 값은 보기): 열 차례는 대상, 기준일, 투자 원금, **시작일 단가**, **기준일 단가**, **등락**, 현재 가치, 비용, 투자 수익, 수익률

  ```
  │ 투자 원금     │ 시작일 단가        │ 기준일 단가        │ 등락          │ 현재 가치 …
  │ ₩10,000,000  │ ₩16,180           │ ₩55,000           │ ▲ ₩38,820     │
  │              │ 2010-01-04         │ 2026-10-07         │ +239.92%      │
  │              │ 분할 반영 50:1      │                    │               │
  │ ₩10,000,000  │ $20.83             │ $289.10            │ ▲ $268.27     │   ← XLK — 상장국 통화
  │ (정기예금)    │ 2.10%  2015-01     │ 2.45% ⏳ 2026-08   │ ▲ 0.35%p  —   │
  ```

  - 단가: 값(주식·부동산 `formatMoneyWithSymbol`, 가상자산은 007 유효 숫자 형식, 금리 `3.45%`) + 아래 작은 글자로 날짜(금리·부동산은 달). 주식 분할이면 "분할 반영 50:1",
    잠정·추정은 ⏳
  - 등락: 첫 줄 차이(▲/▼ + 값, 오르면 빨강·내리면 파랑, 금리는 `%p`), 둘째 줄 등락률(`+12.34%`, 예금 "—"). 값이 없으면 "—"와 까닭(시세 없음 등)
  - 머리 "등락" 정렬(등락률, 예금은 %p — `lib/decimalOrder`), 값 없는 줄은 끝. 칸 도움말(ⓘ): "단가 등락은 1단위 가격만의 변화입니다 — 배당·수수료·세금·환율·적립 시점이
    빠져 수익률과 다릅니다. 주식은 수정주가(분할 반영)입니다"
  - `testid`: `unit-start`, `unit-asof`, `unit-change`
- **반복 2026-10-09b — 마지막 열 "투자 시뮬레이션"**(spec FR-011b): 머리는 화면 읽기용 글자만(`sr-only` "투자 시뮬레이션"). 계산된 줄에 단추 "투자 시뮬레이션"
  (`aria-label="{이름} 투자 시뮬레이션"`), 수집 중·실패 줄은 빈 칸. 누르면 F10
- **반복 2026-10-09c — 백분율 쉼표**(spec FR-021): 수익률·등락률 등 백분율은 정수부를 세 자리마다 쉼표로 끊는다(`+1,761.91%`). F6 상자·F7 막대·F10 모달도 같은 함수다

## F6. 수익률 추이 (FR-015 — 명확화 5)

```
수익률 추이 (KRW) — 선: 보유 중(매도 전) · 끝 점: 매도 후
 ─ XLK   ┄ 삼성전자   ─ SK하이닉스 …(범례: 색 + 선 모양 + 이름)
 [차트 — 대상마다 선, 기준일에 ○ 보유 중 끝 / ● 매도 후]
 ┌ 2024-03-04 ───────────────┐   ← 커서 상자(sourceEvent 좌표)
 │ XLK        +812.40%       │
 │ 삼성전자    값 없음         │
 └───────────────────────────┘
```

- 부품 `CompareReturnChart` — `ok` 대상만 그린다. 선은 메뉴 시계열 `returnRate`, 결측 구간에서 끊는다(`splitSeriesAtGaps`). 잠정 구간은 메뉴 차트처럼 연한 색
- 기준일: 시계열 마지막 날이 `lineEnd.date`보다 앞이면 그 날에 보유 중 점을 더해 잇는다. `afterSaleReturnRate`가 있으면 같은 날에 매도 후 점(속이 찬 원)
- 색 10개 + 실선·점선 번갈아. 범례·커서 상자에 이름. 기준일의 상자는 두 값("보유 중 +2596.48% · 매도 후 +2045.57%")
- `testid`: `compare-chart`, `compare-legend`, `compare-hover`, `compare-basis`

## F8. 조건이 바뀜 (FR-012a — 명확화 6)

- 지금 조건이 결과를 낸 조건과 다르면 표·그래프·지표를 흐린다(`opacity`)
- 그 위에 `role="status"` 띠: "조건이 바뀌었습니다 — 다시 실행하면 반영됩니다 [ 다시 실행 ]"
- 되돌려 같아지면 띠·흐림이 없어진다. 표 정렬은 조건이 아니다
- 흐린 동안 저장 단추는 꺼지고 "다시 실행한 뒤 저장할 수 있습니다"

## F9. 저장과 저장한 비교 (FR-016~FR-019 — 명확화 3)

결과 오른쪽 칸(`TableWithHistory` 배치 — 좁으면 아래로 감긴다):

```
┌ 저장한 비교 ─────────────────────────────┐
│ ⓘ 이 기기의 로컬 DB에 저장됩니다. 지울 때까지 남습니다. │
│ ┌──────────────────────────────────────┐ │
│ │ 주식 3개 · 2020-01-02 · 일시금          │ │
│ │ 주식 · 삼성전자, SK하이닉스, XLK         │ │
│ │ 10-08 12:21 저장   [불러오기] [×]      │ │
│ └──────────────────────────────────────┘ │
│ 아직 저장한 비교가 없습니다. (빈 목록)     │
└──────────────────────────────────────────┘
```

- **저장**: 결과 위 "저장" 단추 → 이름 칸(처음 값 자동 이름 — data-model 2) + "저장"·"취소". 빈 이름이면 저장 단추가 꺼진다. 막힘·결과 없음·흐림이면 저장 단추가 꺼진다
- 목록 칸: 이름, 자산군 · 대상 이름들(셋 넘으면 "외 N개"), 시작일·방식, 저장 시각(`formatKst`). "불러오기"(`aria-label="{이름} 불러오기"`), "×"(`aria-label="{이름} 삭제"`)
- 불러오기: 자산군·방식·조건·대상을 채우고 곧바로 실행한다(FR-017). 지금 결과가 저장되지 않았어도 묻지 않는다(조건만의 기록이라 다시 만들 수 있다)
- 실패(FR-019): 목록 받기 실패 → `role="alert"` + "다시 시도"(012 `HistoryContent`), 저장·삭제 실패 → `role="alert"` 문구, 결과는 그대로
- 안내 문구는 `HistoryNotice`처럼 두되 보관 기간 문장 대신 "지울 때까지 남습니다". 빈 목록 문구는 "아직 저장한 비교가 없습니다." — `HistoryContent`에 빈 목록 문구
  속성을 더한다(처음 값은 지금 문구 — 메뉴 이력 화면 불변)
