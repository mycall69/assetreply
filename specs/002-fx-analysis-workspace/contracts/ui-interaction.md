# UI 상호작용 계약 — 선택 날짜 연동

**Feature**: 002-fx-analysis-workspace | **Date**: 2026-08-30

FR-008·FR-009는 "화면 전체가 하나의 선택 날짜를 공유하고, 어느 곳에서 바꿔도 나머지가
따라온다"를 요구한다. 이 문서는 그 규칙을 고정한다.

---

## 조회 가능 범위의 판정 근거

화면 진입 시 `GET /api/fx/coverage`를 한 번 받아 보관한다. 이 응답이 세 통화 전부의
`coveredFrom`·`coveredThrough`·`firstAvailableDate`를 담으므로 통화를 바꿔도 다시 받지 않는다.

이 값이 두 곳에서 쓰인다.

- 선택 날짜가 조회 가능 범위 안인지 판정(FR-010) — 서버에 묻지 않고 클라이언트가 판단한다
- 기간 프리셋 "전체"의 실제 구간 산정(FR-019)

## 단일 상태 원천

화면은 아래 세 값을 **한 곳에서만** 관리한다.

| 상태 | 초기값 | 바뀌는 계기 |
|------|--------|-------------|
| 선택 통화 | `USD` | 통화 탭 |
| 선택 날짜 | 가장 최근 고시일 | 날짜 입력 / 차트 지정 / 표 행 지정 |
| 차트 기간 | 1년 | 기간 프리셋 |

날짜 입력·차트 강조선·표 강조 행은 **각자 상태를 갖지 않는다.** 셋 다 같은 값을 읽어 그린다.
각자 상태를 두고 서로 동기화하면 어긋나는 순간이 반드시 생기고, SC-002(세 영역이 다른 날짜를
가리키는 사례 0건)를 만족할 수 없다.

---

## 변경 경로

```text
  ┌─────────────┐
  │ 날짜 입력   │──┐
  └─────────────┘  │
  ┌─────────────┐  │    ┌──────────────┐    ┌─────────────┐
  │ 차트 지정   │──┼───▶│ 선택 날짜     │───▶│ 날짜 입력   │
  └─────────────┘  │    │ (단일 상태)   │    │ 차트 강조선 │
  ┌─────────────┐  │    └──────────────┘    │ 표 강조 행  │
  │ 표 행 지정  │──┘                        └─────────────┘
  └─────────────┘
```

세 입력 중 어느 것이든 상태를 바꾸고, 세 표시가 모두 그 상태를 읽는다.

---

## 각 경로의 규칙

### 날짜 입력

- 사용자가 임의 날짜를 넣을 수 있다. **고시가 없는 날도 선택 가능하다** — 그 사실을 알리는
  것이 화면의 역할이다(W3-a).
- 현재 통화의 조회 가능 범위를 벗어나면 범위를 알리고 상태를 바꾸지 않는다(FR-010).

### 차트에서 지정

- 사용자가 지정한 x좌표에 **가장 가까운 실제 포인트의 날짜**를 선택 날짜로 삼는다.
  좌표를 그대로 날짜로 환산하면 고시가 없는 날이 선택되어 매번 "고시 없음"이 뜬다.
- 다운샘플링된 구간에서는 화면에 그려진 점 중 가장 가까운 것을 고른다. 표시되지 않은 점을
  선택하면 사용자가 짚은 곳과 강조선이 어긋난다.

### 표에서 지정

- 행을 지정하면 그 행의 날짜가 선택 날짜가 된다. 표의 모든 행은 실제 고시일이므로 항상
  유효하다.

---

## 통화 변경 시 (FR-007)

통화를 바꾸면 요약·차트·표가 모두 새 통화로 갱신된다. **선택 날짜는 유지한다.**

- 새 통화의 조회 가능 범위 밖이면 그 사실을 알리고, 선택 날짜를 새 통화의 가장 최근 고시일로
  옮긴다. 예: EUR(1994~)에서 1970년을 선택한 채 USD로 바꾸면 유지되지만, 그 반대는 옮겨진다.
- 통화마다 축적 시작일이 다르다는 사실이 여기서 드러난다(001 FR-002).

---

## 기간 변경 시 (FR-015, FR-019)

- 기간 프리셋은 차트만 바꾼다. **표는 영향받지 않는다**(research R2-6, 표와 차트는 독립).
- 선택 날짜가 새 기간 밖으로 벗어나면 강조선이 보이지 않는다. 이때 선택 날짜를 바꾸지 않고,
  차트에 "선택한 날짜가 현재 기간 밖입니다"를 표시한다. 사용자가 고른 날짜를 시스템이 임의로
  바꾸지 않는다.
- 프리셋이 요구하는 구간이 통화의 축적 시작일보다 이르면 실제 축적 범위만 그리고 그 사실을
  알린다(FR-019).

---

## 갱신 범위 최소화

어떤 조작이 어떤 데이터를 다시 받는지 고정한다. SC-005(스프레드 변경 후 2초)와
SC-009a(첫 진입 3초)가 여기에 달려 있다.

| 조작 | 요약 | 차트 | 표 |
|------|:----:|:----:|:--:|
| 첫 진입 | ● | ● | ● |
| 통화 변경 | ● | ● | ● |
| 선택 날짜 변경 (표 범위 안) | — | — | — |
| 선택 날짜 변경 (표 범위 밖) | — | — | ●(그 날짜 기준 재로드) |
| 기간 프리셋 변경 | — | ● | — |
| 스프레드 저장·복원 | ● | — | ● |
| 오늘 새로고침 | ● | ● | ● |
| 표 "더 보기" | — | — | ●(추가분만) |

**선택 날짜 변경이 대체로 아무것도 다시 받지 않는 것**이 핵심이다. 예외는 선택 날짜가 표의
현재 표시 범위 밖일 때뿐이며, 이때만 표를 `before = 선택날짜 + 1일`로 다시 받아 그 날짜가
첫 행이 되게 한다(FR-022a). 강조할 행이 없는 채로 두면 사용자는 차트에서 짚은 시점의 파생
환율을 볼 방법이 없다.

그 밖의 경우 세 영역은 이미 가진 데이터로 강조 위치만 바꾼다. 날짜를 옮길 때마다 서버를
부르면 차트 위에서 시점을 훑는 조작이 느려진다(SC-009: 1초 이내).

스프레드 변경이 차트를 건드리지 않는 이유는 차트가 매매기준율만 그리기 때문이다. 파생 환율은
차트에 없다.
