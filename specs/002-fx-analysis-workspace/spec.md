# Feature Specification: 외환 분석 화면 통합과 전역 내비게이션 셸

**Feature Branch**: `002-fx-analysis-workspace`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "외환(FX) 화면을 단일 분석 페이지로 재구성하고, 자산군 전역 내비게이션 셸을 도입한다. 001의 4개 탭(조회/스프레드/차트/수집현황)을 하나의 분석 화면으로 합치고, 스프레드 설정을 설정 메뉴로 옮기며(기본값 복원 포함), 오늘 환율을 새로고침할 수 있게 한다."

## Clarifications

### Session 2026-08-30

- Q: 오늘 잠정값을 축적 시계열에 저장하는가, 화면 표시용으로만 유지하는가? → A: 시계열에
  저장하되 확정/잠정 구분 표시를 함께 둔다. 조회 경로가 하나로 유지되고, 화면을 열 때마다
  외부를 호출하지 않는다.
- Q: 요약의 "가장 최근 매매기준율"이 오늘 잠정값인가 마지막 확정값인가? → A: 오늘 잠정값이
  있으면 그것을, 없으면 마지막 확정값을 제시하고 어느 쪽인지 표시한다.
- Q: 잠정으로 저장된 오늘 값이 언제 확정 상태로 바뀌는가? → A: 날짜가 지나면 기존 증분 수집
  경로가 그 날짜를 다시 받아오고, 받아온 값으로 덮으면서 확정으로 기록한다. 값을 다시 받지
  않고 상태만 바꾸지 않는다.
- Q: 같은 통화의 대량 수집이 진행 중일 때 오늘 환율 새로고침을 누르면 어떻게 되는가? → A:
  새로고침은 기존 수집 잠금과 무관하게 동작한다. 다만 같은 통화의 새로고침끼리는 하나만
  실행되고 중복 요청은 진행 중인 것에 합류한다.
- Q: 오늘의 잠정값이 추이 차트에도 표시되는가? → A: 차트에 포함하되 확정 구간과 시각적으로
  구분한다. 표시 점 수를 줄이는 처리를 하더라도 가장 최근 값은 항상 남긴다.
- Q: 외환 화면 첫 진입 시 요약·차트·표가 몇 초 안에 보여야 하는가? → A: 이미 수집된 구간을
  볼 때 모든 구성 요소가 3초 이내에 표시된다(001의 조회 기준과 동일).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 한 화면에서 환율과 실거래 기준 가격을 함께 확인 (Priority: P1)

투자 판단을 하려는 사용자가 왼쪽 메뉴에서 외환을 선택하고, 통화를 고른 뒤 날짜를 지정하면
그날의 매매기준율과 실제 거래에 적용되는 4종 파생 환율을 **한 화면에서** 확인한다. 최근
며칠의 값도 표로 함께 보여 어제와 오늘 중 언제가 유리했는지 바로 비교한다.

**Why this priority**: 001의 가장 큰 결함을 해소한다. 지금은 "얼마였나"를 알기 위해 조회 탭에서
값을 보고, 스프레드 탭으로 옮겨 설정을 확인하고, 다시 돌아와야 한다. 하나의 질문에 세 번의
화면 이동이 필요하다. 이 스토리만 구현해도 완결된 가치가 나온다.

**Independent Test**: 사이드바에서 외환으로 이동해 통화와 날짜를 지정했을 때, 매매기준율과
파생 환율 4종이 한 화면에 나타나고 최근 고시일 목록이 함께 보이는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 어느 화면에 있든, **When** 왼쪽 메뉴에서 외환을 선택하면,
   **Then** 외환 분석 화면으로 이동하고 메뉴에서 현재 위치가 강조된다.
2. **Given** 외환 화면이 열렸을 때, **When** 사용자가 통화를 USD에서 JPY로 바꾸면,
   **Then** 요약·표를 포함한 화면의 모든 값이 JPY 기준으로 바뀐다.
3. **Given** 통화가 선택된 상태에서, **When** 화면이 표시되면,
   **Then** 가장 최근 매매기준율이 화면에서 가장 큰 숫자로 제시되고, 그 값의 기준 날짜와
   통화쌍이 함께 드러난다.
4. **Given** 요약이 표시되었을 때, **When** 사용자가 값을 보면,
   **Then** 직전 고시일 대비 변화량이 절대값과 백분율로 함께 표시되고 상승·하락이 구분된다.
5. **Given** 화면이 표시되었을 때, **When** 사용자가 상세 표를 보면,
   **Then** 최근 고시일부터 과거 순으로 날짜·매매기준율·파생 환율 4종이 나열된다.
6. **Given** 표가 표시되었을 때, **When** 사용자가 파생 환율을 보면,
   **Then** 그 값이 현재 설정된 스프레드를 과거에 적용한 가정임이 화면에 드러난다.
7. **Given** 사용자가 날짜를 지정했을 때, **When** 그 날짜에 고시가 있으면,
   **Then** 표에서 해당 행이 시각적으로 강조된다.
8. **Given** 사용자가 아직 준비되지 않은 자산군 메뉴를 볼 때, **When** 그 항목을 확인하면,
   **Then** 준비 중임이 드러나며 빈 화면이나 오류로 이어지지 않는다.

### User Story 2 - 추이를 보고 특정 시점을 짚어낸다 (Priority: P2)

사용자가 기간을 선택해 환율 추이를 보고, 관심 시점을 차트 위에서 직접 지정한다. 지정한
시점은 날짜 입력과 상세 표에도 함께 반영되어 세 영역이 같은 날짜를 가리킨다.

**Why this priority**: 단일 날짜만으로는 "그때가 좋았나"를 판단할 수 없다. 다만 조회(US1)가
동작한 뒤에야 의미가 있으므로 P2다.

**Independent Test**: 기간을 선택해 차트를 띄운 뒤 임의 시점을 지정했을 때, 차트의 강조선과
날짜 입력, 표의 강조 행이 모두 같은 날짜를 가리키는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 통화가 선택된 상태에서, **When** 사용자가 기간 프리셋을 고르면,
   **Then** 그 구간의 추이가 차트로 표시되고 선택된 기간이 차트 제목에 함께 드러난다.
2. **Given** 선택 날짜가 지정되어 있을 때, **When** 차트가 그려지면,
   **Then** 그 날짜 위치에 세로 강조선과 날짜 라벨이 표시되고, 곡선과 만나는 지점에 표식이 놓인다.
3. **Given** 차트가 표시된 상태에서, **When** 사용자가 차트의 한 시점을 지정하면,
   **Then** 날짜 입력과 표의 강조 행이 그 날짜로 함께 이동한다.
4. **Given** 사용자가 표의 한 행을 지정할 때, **When** 그 행이 선택되면,
   **Then** 날짜 입력과 차트 강조선이 그 날짜로 함께 이동한다.
5. **Given** 표시 구간에 고시가 없는 날이 포함될 때, **When** 차트가 그려지면,
   **Then** 시스템은 없는 값을 만들어 이어 붙이지 않고 그 구간이 비어 있음을 알아볼 수 있게 표현한다.
6. **Given** 선택 날짜에 고시가 없을 때, **When** 화면이 갱신되면,
   **Then** 고시가 없다는 사실이 드러나고, 표에 강조할 행이 없음이 사용자에게 혼란을 주지 않는다.

### User Story 3 - 스프레드를 조정하고 언제든 기본값으로 되돌린다 (Priority: P2)

사용자가 설정 메뉴에서 통화별 스프레드를 조정한다. 값을 이것저것 바꿔본 뒤 원래대로
되돌리고 싶을 때 기본값 복원으로 한 번에 돌아간다.

**Why this priority**: 파생 환율이 화면의 절반을 차지하므로 스프레드 조정 수단이 필요하다.
복원이 없으면 사용자는 실험을 꺼리거나 기본값을 따로 적어둔다. 조회(US1)가 동작한 뒤에
의미가 있으므로 P2다.

**Independent Test**: 설정에서 값을 바꾸고 저장한 뒤 외환 화면의 파생 환율이 바뀌는지,
복원 후 원래 값으로 돌아오는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 설정 메뉴에 들어갔을 때, **When** 외화 스프레드 화면을 보면,
   **Then** USD, JPY, EUR 순서로 각 통화의 4종 스프레드가 현재 값과 함께 표시된다.
2. **Given** 스프레드 값을 바꿨을 때, **When** 저장하면,
   **Then** 외환 화면의 요약과 표의 파생 환율이 새 값 기준으로 다시 산출된다.
3. **Given** 사용자가 허용 범위를 벗어난 값을 입력할 때, **When** 저장을 시도하면,
   **Then** 시스템은 해당 입력 옆에서 무엇이 잘못됐는지 알리고 기존 값을 유지한다.
4. **Given** 값을 바꾼 상태에서, **When** 사용자가 기본값 복원을 요청하면,
   **Then** 시스템은 복원 범위를 알리고 확인을 받은 뒤 정해진 기본값으로 되돌린다.
5. **Given** 복원 확인 단계에서, **When** 사용자가 취소하면,
   **Then** 현재 값이 그대로 유지된다.
6. **Given** 현재 값이 기본값과 다를 때, **When** 사용자가 설정 화면을 보면,
   **Then** 기본값에서 벗어나 있음이 드러난다.

### User Story 4 - 오늘 환율을 최신 상태로 새로고침한다 (Priority: P3)

오늘 환율은 장중에 계속 바뀐다. 사용자가 원할 때 오늘 값만 다시 받아와 최신 상태를 확인하고,
그 값이 아직 확정된 값이 아님을 인지한 채로 판단한다.

**Why this priority**: 없어도 과거 데이터 분석은 완결된다. 다만 "지금 환전하면 얼마인가"를
묻는 사용자에게는 어제 값만으로 부족하다. 확정 데이터 기반이 갖춰진 뒤에 붙는 기능이므로 P3다.

**Independent Test**: 새로고침을 실행했을 때 오늘 값이 갱신되고 마지막 갱신 시각이 바뀌는지,
그 값이 확정값과 구분되어 표시되는지로 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 외환 화면이 표시된 상태에서, **When** 사용자가 오늘 환율 새로고침을 실행하면,
   **Then** 오늘 하루치만 다시 받아오고 과거 구간은 다시 요청하지 않는다.
2. **Given** 오늘 값이 표시될 때, **When** 사용자가 그 값을 보면,
   **Then** 확정된 과거 값과 시각적으로 구분되어 아직 확정 전임이 드러난다.
3. **Given** 새로고침이 완료됐을 때, **When** 사용자가 화면을 보면,
   **Then** 마지막으로 받아온 시각이 표시된다.
4. **Given** 오늘 고시가 아직 없거나 오늘이 고시 없는 날일 때, **When** 새로고침을 실행하면,
   **Then** 시스템은 그 사실을 알리고 값을 만들어내지 않는다.
5. **Given** 새로고침이 실패했을 때, **When** 오류가 발생하면,
   **Then** 이미 표시 중인 값과 저장된 과거 데이터는 그대로 유효하며 실패 사유가 전달된다.
6. **Given** 오늘 값이 잠정인 상태에서, **When** 그 값으로 파생 환율이 산출되면,
   **Then** 산출된 파생 환율에도 잠정임이 드러난다.
7. **Given** 오늘 값이 여러 번 갱신됐을 때, **When** 사용자가 과거 확정 구간을 조회하면,
   **Then** 확정 구간의 값은 새로고침 이전과 동일하다.

### User Story 5 - 표의 내용을 파일로 내려받는다 (Priority: P3)

사용자가 화면의 일자별 환율 상세를 파일로 내려받아 별도 도구에서 가공하거나 보관한다.

**Why this priority**: 화면에서 값을 읽는 것만으로 충족되는 사용자가 다수이므로 P3다.
다만 스프레드를 반영한 4종 파생 환율을 손으로 옮겨 적는 것은 오류를 부른다.

**Independent Test**: 내려받기를 실행했을 때 화면의 표와 같은 내용이 담긴 파일이 생성되는지로
단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 표가 표시된 상태에서, **When** 사용자가 내려받기를 실행하면,
   **Then** 표의 날짜·매매기준율·파생 환율 4종이 담긴 파일이 생성된다.
2. **Given** 파일에 값이 담길 때, **When** 사용자가 파일을 열면,
   **Then** 숫자의 정밀도가 화면에 표시된 값과 일치한다.
3. **Given** 내려받은 내용에 잠정값이 포함될 때, **When** 사용자가 파일을 열면,
   **Then** 어느 값이 잠정인지 구분할 수 있다.
4. **Given** 파일이 생성될 때, **When** 사용자가 내용을 확인하면,
   **Then** 어떤 통화의 어느 구간이며 어떤 스프레드가 적용됐는지 알 수 있다.

---

### Edge Cases

- 선택 날짜에 고시가 없을 때(주말·공휴일) 요약·차트·표가 각각 무엇을 보여주는가?
- 선택 날짜가 해당 통화의 수집 완료 구간 시작 이전이거나 미래일 때 어떻게 응답하는가?
- 통화를 바꿨을 때 선택 날짜가 새 통화의 축적 범위 밖이면 어떻게 되는가?
- 기간 프리셋이 해당 통화의 축적 시작일보다 긴 구간을 요구하면 어떻게 표현하는가?
- 차트 요청 구간에 미수집 구간이 있을 때 화면이 어떻게 반응하는가?
- 오늘 값을 새로고침하는 도중 사용자가 통화를 바꾸면 어떻게 되는가?
- 대량 수집과 오늘 새로고침이 같은 통화에서 동시에 진행될 때 서로를 방해하지 않는가?
- 오늘 값이 잠정 상태에서 다음 날 확정으로 바뀔 때 값이 달라졌다면 추적할 수 있는가?
- 잠정 레코드가 남은 날짜를 증분 수집이 건너뛰어 영원히 확정되지 않는 상황이 생기지 않는가?
- 스프레드를 0으로 설정하면 파생 환율 4종이 모두 매매기준율과 같아지는가?
- 선택 날짜가 표에 현재 표시된 범위보다 과거일 때 표가 어떻게 반응하는가?
- 기본값 복원 중 일부 통화만 실패하면 어떤 상태로 남는가?
- 표에 표시할 고시일이 하나도 없을 때(수집 전) 화면이 어떻게 보이는가?
- 아직 준비되지 않은 자산군 메뉴를 선택하면 어떻게 되는가?

## 용어

확정과 잠정은 헌법 v5.0.0 원칙 V가 정한 개념이다. 이 문서에서는 아래 뜻으로만 쓴다.

| 용어 | 뜻 | 판별 기준 |
|------|-----|-----------|
| **확정(confirmed)** | 출처가 마감해 더 이상 바뀌지 않는 값 | 어제 이하의 날짜를 정규 수집 경로로 받아온 값 |
| **잠정(provisional)** | 출처가 아직 마감하지 않아 바뀔 수 있는 값 | 오늘 날짜를 새로고침 경로로 받아온 값 |
| **정정(correction)** | 출처가 이미 마감한 값을 나중에 고친 것 | 확정값이 다른 값으로 재수신됨 |

**정정은 잠정이 아니다.** 정정된 값은 여전히 확정이며, 001의 FR-003a 규칙(최신 값으로
갱신하고 원본은 보존)을 따른다. 잠정은 "아직 마감되지 않음"이고 정정은 "마감됐으나 고쳐짐"이다.
둘을 섞으면 재현성 보장의 경계가 흐려진다.

## Requirements *(mandatory)*

### Functional Requirements

**전역 내비게이션 셸**

- **FR-001**: 시스템은 모든 화면에서 접근 가능한 고정 내비게이션 영역을 제공해야 하며, 여기에
  제품 이름과 자산군별 진입점을 배치해야 한다.
- **FR-002**: 내비게이션은 대시보드, 외환, 주식, 가상자산, 예금, 부동산, 투자 비교, 설정
  항목을 포함해야 한다.
- **FR-003**: 시스템은 현재 사용자가 보고 있는 화면이 어느 항목인지 내비게이션에서
  구별되게 표시해야 한다.
- **FR-004**: 시스템은 현재 화면의 이름을 화면 상단에 표시해야 한다.
- **FR-005**: 아직 구현되지 않은 자산군 항목은 준비 중임을 사용자에게 알려야 하며, 선택 시
  빈 화면이나 오류를 제시해서는 안 된다.

**외환 화면 — 통화와 선택 날짜**

- **FR-006**: 사용자는 USD, JPY, EUR 중 하나를 선택할 수 있어야 하며, 동시에 하나만 선택된다.
  각 선택지는 통화 코드와 한글 이름을 함께 제시해야 한다.
- **FR-007**: 통화를 변경하면 화면의 요약, 차트, 상세 표가 모두 새 통화 기준으로 갱신되어야 한다.
- **FR-008**: 시스템은 화면 전체가 공유하는 하나의 "선택 날짜"를 유지해야 한다.
- **FR-009**: 사용자는 날짜 입력, 차트의 시점 지정, 상세 표의 행 지정 중 어느 방법으로도
  선택 날짜를 바꿀 수 있어야 하며, 한 곳에서 바꾸면 나머지가 함께 따라와야 한다.
- **FR-010**: 선택 날짜가 현재 통화의 조회 가능 범위를 벗어나면 시스템은 조회 가능한 범위를
  알리고 값을 반환하지 않아야 한다.

**외환 화면 — 요약**

- **FR-011**: 시스템은 현재 통화의 가장 최근 매매기준율을 화면에서 가장 큰 시각적 비중으로
  제시해야 한다. 오늘의 잠정값이 있으면 그 값을, 없으면 마지막 확정값을 제시한다.
- **FR-012**: 요약에는 통화쌍 표기와 그 값이 어느 날짜의 값인지가 포함되어야 한다.
- **FR-013**: 시스템은 요약에 제시된 값과 그 직전 고시일 값의 차이를 절대값과 백분율로 함께
  제시하고, 상승과 하락을 방향 기호와 색으로 구별해야 한다. 요약이 잠정값일 때의 비교 대상은
  직전 확정값이다.
- **FR-014**: 요약에 제시된 값이 잠정인지 확정인지를 사용자가 구별할 수 있어야 하며, 잠정인
  경우 확정 전임이 값 근처에서 드러나야 한다. 구분은 색 외의 수단(문구·기호·선 형태)을 함께
  써야 하며 색 하나에만 의존해서는 안 된다. 이 규칙은 차트(FR-017a)와 표(FR-025)의 잠정
  구분에도 동일하게 적용된다.

**외환 화면 — 추이 차트**

- **FR-015**: 사용자는 미리 정의된 기간 프리셋으로 차트 구간을 선택할 수 있어야 하며, 현재
  선택된 기간이 차트 제목에 드러나야 한다.
- **FR-016**: 시스템은 선택 날짜 위치에 세로 강조선과 날짜 라벨을 표시하고, 추이 곡선과
  만나는 지점에 표식을 두어야 한다.
- **FR-017**: 차트는 표시 구간 내의 미수집 구간과 고시 없는 날에 대해 값을 만들어 이어 붙이지
  않고, 해당 구간이 비어 있음을 알아볼 수 있게 표현해야 한다.
- **FR-017a**: 오늘의 잠정값은 차트에도 표시해야 하며, 확정 구간과 시각적으로 구분되어야 한다.
  요약과 차트의 마지막 시점이 어긋나서는 안 된다.
- **FR-017b**: 표시 점 수를 줄이는 처리를 적용하더라도 구간의 가장 최근 값은 항상 표시되어야
  한다. 최적화 때문에 오늘 값이 사라져서는 안 된다.
- **FR-018**: 선택 날짜에 고시가 없으면 강조선이 값을 가리키지 않는다는 사실이 드러나야 한다.
- **FR-019**: 프리셋이 요구하는 구간이 해당 통화의 축적 시작일보다 이르면, 시스템은 실제
  축적된 범위만 표시하고 그 사실을 알려야 한다.

**외환 화면 — 일자별 상세 표**

- **FR-020**: 시스템은 최근 고시일부터 과거 순으로 날짜, 매매기준율, 현금 살 때, 현금 팔 때,
  송금 보낼 때, 송금 받을 때를 표로 제시해야 한다.
- **FR-021**: 고시가 없는 날은 표에 행을 만들지 않아야 한다. 값을 만들어 채우거나 인접일 값을
  복사해서는 안 된다.
- **FR-022**: 시스템은 선택 날짜에 해당하는 행을 시각적으로 강조해야 한다.
- **FR-022a**: 선택 날짜가 표에 표시된 범위 밖이면, 시스템은 그 날짜가 포함되도록 표를
  다시 제시해야 한다. 강조할 행이 없는 채로 남겨두어서는 안 된다.
- **FR-023**: 파생 환율 4종은 현재 설정된 스프레드를 적용해 산출해야 하며, 저장하지 않고
  조회 시점에 계산해야 한다.
- **FR-024**: 시스템은 파생 환율이 "현재 스프레드 조건을 과거 시점에 적용한 가정"임을 화면에서
  밝혀야 한다.
- **FR-025**: 표에 잠정값 행이 포함되면 확정값 행과 구별되어야 한다.
- **FR-026**: 사용자는 표에 표시된 범위보다 더 과거의 고시일을 이어서 볼 수 있어야 한다.

**설정 — 외화 스프레드**

- **FR-027**: 시스템은 설정 화면에서 통화별 스프레드를 조회·변경할 수 있게 해야 하며, 통화를
  USD, JPY, EUR 순서로 제시해야 한다.
- **FR-028**: 각 통화마다 현금 살 때, 현금 팔 때, 송금 보낼 때, 송금 받을 때 4종을 개별로
  설정할 수 있어야 한다.
- **FR-029**: 시스템은 0 이상 1 미만의 값만 허용해야 하며, 범위를 벗어난 입력은 거부하고 기존
  값을 유지하되 어떤 입력이 왜 거부됐는지 해당 입력 근처에서 알려야 한다.
- **FR-030**: 스프레드를 설정하지 않은 통화에는 정해진 기본값이 적용되어야 한다. 기본값은
  아래와 같다.

  | 통화 | 현금 살 때 | 현금 팔 때 | 송금 보낼 때 | 송금 받을 때 |
  |------|-----------|-----------|-------------|-------------|
  | USD  | 0.001800  | 0.001800  | 0.000500    | 0.000500    |
  | JPY  | 0.002000  | 0.002000  | 0.000600    | 0.000600    |
  | EUR  | 0.002000  | 0.002000  | 0.000600    | 0.000600    |

- **FR-031**: 사용자는 스프레드를 FR-030의 기본값으로 되돌릴 수 있어야 한다.
- **FR-031a**: 전 통화 복원 중 일부가 실패하면 시스템은 어떤 통화가 복원되고 어떤 통화가
  실패했는지 알려야 한다. 성공한 복원을 되돌리지 않는다.
- **FR-032**: 복원을 실행하기 전에 시스템은 복원 대상 범위를 알리고 사용자의 확인을 받아야
  한다. 확인 없이 값이 바뀌어서는 안 된다.
- **FR-033**: 시스템은 현재 값이 기본값과 다른지를 사용자가 알 수 있게 표시해야 한다.
- **FR-034**: 스프레드가 변경되거나 복원되면 외환 화면의 요약과 표의 파생 환율이 새 값 기준으로
  다시 제시되어야 한다.
- **FR-035**: 스프레드는 시스템 전역에 통화별로 하나씩만 존재하며, 현재 값이 모든 과거 날짜에
  동일하게 적용되어야 한다. 시점별 이력은 관리하지 않는다.

**오늘 환율 새로고침**

- **FR-036**: 사용자는 오늘 하루치 환율만 다시 받아오도록 요청할 수 있어야 한다. 이 요청이
  과거 구간의 재수집을 유발해서는 안 된다.
- **FR-036a**: 오늘 환율 새로고침은 기존 수집 작업의 통화별 단일 실행 제약과 독립적으로
  동작해야 한다. 대량 수집이 진행 중이라는 이유로 새로고침이 거부되어서는 안 된다.
  두 작업의 대상 구간은 겹치지 않는다(수집은 어제까지, 새로고침은 오늘만).
- **FR-036b**: 같은 통화에 대한 새로고침은 동시에 하나만 실행되어야 하며, 진행 중에 다시
  요청되면 새 요청을 만들지 않고 진행 중인 요청의 결과를 사용해야 한다.
- **FR-036c**: 새로고침이 진행 중일 때 사용자가 통화를 바꾸면, 진행 중인 요청의 결과가 바뀐
  통화의 화면에 반영되어서는 안 된다. 요청은 시작 시점의 통화에 귀속된다.
- **FR-037**: 오늘 값은 축적 시계열에 저장하되, 확정값과 구별되는 상태를 함께 기록해야 한다.
  확정 여부를 구분하지 않고 저장하거나 표시해서는 안 된다.
- **FR-037a**: 시스템은 잠정으로 저장된 값을 기존 증분 수집 경로가 그 날짜를 다시 받아올 때
  실제 값으로 덮고 확정으로 기록해야 한다. 값을 다시 받아 확인하지 않은 채 상태만 확정으로
  바꿔서는 안 된다. 확정 전까지는 재조회 시 값이 달라질 수 있음을 전제로 다뤄야 한다.
  **값을 덮는 것과 상태를 확정으로 바꾸는 것은 하나의 동작이다.** 값만 갱신하고 상태를 그대로
  두면 오류가 나지 않은 채 잠정 표시가 영구히 남고, 출처가 정정해도 사용자는 알 수 없다.
- **FR-037b**: 잠정 상태로 저장된 날짜는 수집이 완료된 구간으로 취급해서는 안 된다. 잠정
  레코드가 존재한다는 이유로 그 날짜의 확정값 수집이 생략되어서는 안 된다.
- **FR-037c**: 잠정 상태의 레코드는 통화당 최대 하나이며 그 날짜는 오늘이어야 한다. 과거
  날짜에 잠정 레코드가 남아 있다면 확정 전환이 일어나지 않은 것이므로 결함이다.
- **FR-037d**: 확정된 값이 다시 잠정으로 되돌아가서는 안 된다. 전이는 잠정 → 확정 한 방향뿐이다.
- **FR-038**: 시스템은 오늘 값을 마지막으로 받아온 시각을 사용자에게 제시해야 한다.
- **FR-039**: 오늘 고시가 아직 없거나 오늘이 고시 없는 날이면 시스템은 그 사실을 알려야 하며,
  값을 생성하거나 인접일 값으로 대체해서는 안 된다.
- **FR-040**: 새로고침이 실패해도 이미 표시 중인 값과 저장된 과거 데이터는 유효한 상태로
  유지되어야 하며, 실패 사유가 사용자에게 전달되어야 한다.
- **FR-041**: 잠정값이 파생 환율 산출에 사용되면 그 결과에도 잠정임이 드러나야 한다.
- **FR-042**: 잠정값의 변동이 확정된 과거 값에 영향을 주어서는 안 된다. 확정 구간을 반복
  조회하면 항상 같은 값이 반환되어야 한다.
- **FR-042a**: 시스템은 확정값만을 대상으로 하는 조회 경로를 제공해야 한다. 이 경로가
  SC-003(확정 구간 재현성)이 성립하는 근거이며, 화면용 조회는 잠정을 포함하되 상태를 함께
  전달해 구분할 수 있게 한다.
- **FR-043**: 잠정에서 확정으로 전환된 시점과 그때의 값 변화는 사후에 추적할 수 있어야 한다.
  전환 시점은 해당 레코드의 마지막 갱신 시각으로, 값 변화는 잠정 시점과 확정 시점에 수신한
  **원본 응답 기록 두 건을 대조**해 확인한다. 별도의 전환 이력을 만들지 않는다.
- **FR-043a**: 오늘이 지났는데도 잠정 레코드가 남아 있으면 시스템은 **수집 현황 화면에서**
  통화별로 그 사실과 해당 날짜를 표시해야 한다. 잔존이 여러 날 있으면 가장 오래된 날짜를
  제시한다 — 어제부터 남은 것과 열흘 전부터 남은 것은 심각도가 다르다.
  출처가 그 날짜의 값을 끝내 제공하지 않는 경우(뒤늦게 휴장일로 확정되는 등)에도 **표시는
  유지되어야 한다.** 시스템은 출처가 값을 주도록 강제할 수 없으므로, 할 수 있는 일은
  드러내는 것뿐이다. 표시가 사라지면 운영자는 잊는다.
  잠정 잔존은 확정 전환이 일어나지 않았음을 뜻하므로, 표시에는 **무엇을 하면 해소되는지**
  (해당 통화의 증분 수집 실행)가 함께 드러나야 한다. 원인을 알려주지 않는 경고는 운영자가
  할 수 있는 일이 없다.
- **FR-043b**: 오늘 날짜의 잠정은 정상 상태이므로 잔존으로 표시해서는 안 된다. 매일 경고가
  뜨면 신호로서 쓸모가 없어진다.

**내려받기**

- **FR-044**: 사용자는 일자별 상세 표의 내용을 파일로 내려받을 수 있어야 한다.
- **FR-045**: 내려받은 파일의 수치는 화면에 표시된 값과 정밀도가 일치해야 한다.
- **FR-046**: 내려받은 내용에는 어떤 통화의 어느 구간이며 어떤 스프레드가 적용됐는지가
  포함되어야 한다.
- **FR-047**: 내려받은 내용에 잠정값이 포함되면 확정값과 구별할 수 있어야 한다. 구분은 값
  자체를 변형하지 않고 **별도 항목**으로 표기한다 — 값에 기호를 덧붙이면 별도 도구에서
  숫자로 읽히지 않는다.

**수집 연동**

- **FR-048**: 조회 구간에 미수집 구간이 있으면 시스템은 기존 자동 수집 규칙을 그대로 적용해야
  한다.
- **FR-049**: 수집이 진행 중일 때 시스템은 그 사실을 사용자가 인지할 수 있도록 셸에서 알려야
  한다.

### Key Entities *(include if feature involves data)*

- **화면 선택 상태**: 사용자가 현재 보고 있는 조합. 선택 통화, 선택 날짜, 차트 기간을 가진다.
  화면의 모든 구성 요소가 이 상태 하나를 공유한다.
- **고시값의 확정 상태**: 각 환율 레코드가 확정인지 잠정인지를 나타내는 구분. 잠정값은 재조회
  시 달라질 수 있으며, 확정으로 전환된 시점을 추적할 수 있어야 한다.
- **스프레드 설정**: 통화별 4종 비율. 시스템 전역에 통화당 하나씩 존재하며 기본값을 가진다.
- **내비게이션 항목**: 자산군 또는 기능으로 이동하는 진입점. 이름, 준비 여부, 현재 선택 여부를
  가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 특정 통화·날짜의 매매기준율과 파생 환율 4종을 확인하기까지 화면 이동
  없이, 통화 선택과 날짜 지정 2회의 조작만으로 도달한다.
- **SC-002**: 사용자가 선택 날짜를 바꾸면 요약·차트 강조·표 강조 세 영역이 모두 같은 날짜를
  가리키며, 서로 다른 날짜를 가리키는 사례가 0건이다.
- **SC-003**: 확정된 과거 날짜를 반복 조회했을 때 항상 동일한 값이 반환된다(재현성 100%).
  오늘 값의 갱신은 이 보장에 영향을 주지 않는다.
- **SC-004**: 고시가 없는 날에 대해 시스템이 만들어낸 값을 표나 차트에 제시하는 사례가 0건이다.
- **SC-005**: 사용자는 스프레드를 변경한 뒤 2초 이내에 갱신된 파생 환율을 확인한다.
- **SC-006**: 사용자는 기본값 복원을 3회 이하의 조작으로 완료하며, 확인 없이 값이 바뀌는
  사례가 0건이다.
- **SC-007**: 오늘 값이 요약·차트·표 어디에 표시되든 확정값과 구별되지 않는 사례가 0건이다.
- **SC-007a**: 요약이 가리키는 시점과 차트의 마지막 표시 시점이 어긋나는 사례가 0건이다.
- **SC-007b**: 오늘이 지난 잠정 레코드가 존재할 때 수집 현황 화면에 표시되지 않는 사례가
  0건이며, 오늘 날짜의 잠정이 잔존으로 표시되는 사례도 0건이다.
- **SC-008**: 오늘 환율 새로고침 1회가 데이터 제공처 호출을 1회만 소비한다.
- **SC-009**: 사용자는 축적된 전 구간 차트에서 확대·이동·시점 지정 조작 시 1초 이내에 화면
  반응을 받는다.
- **SC-009a**: 이미 수집된 구간을 볼 때, 외환 화면에 진입한 시점부터 요약·차트·표가 모두
  3초 이내에 표시된다. 진입 시 함께 받는 축적 범위 조회도 이 3초 안에 포함된다.
  미수집 구간이 있어 자동 수집이 유발되는 경우는 FR-048의 규칙을 따른다.
- **SC-010**: 내려받은 파일의 모든 수치가 화면 표시값과 일치한다(불일치 0건).
- **SC-011**: 준비되지 않은 자산군 메뉴를 선택했을 때 오류 화면이나 빈 화면에 도달하는 사례가
  0건이다.

## Assumptions

명세에 명시되지 않은 부분에 대해 아래 기본값을 선택했다. `/speckit-clarify` 단계에서 뒤집을 수 있다.

- **기존 기능의 재사용**: 001의 수집·저장 계층과 자동 수집 규칙, 스프레드 계산식, 고시 없는 날
  판정 방식을 그대로 사용한다. 이번 범위는 표현 계층의 재구성과 오늘 값 취급의 도입이다.
- **001 재개 규칙과의 관계**: 001의 FR-011(재개는 수집 완료 지점 다음날부터)은 그대로 유효하다.
  FR-037b가 잠정을 커버리지에서 제외하는 이유가 바로 이 규칙과 맞물리기 위해서다. 001의 영업일
  판정("수집 완료 구간 안인데 값이 없는 날 = 고시 없음")도 오늘이 커버리지 밖이므로 오답을
  내지 않는다.
- **재현성 기준의 범위 차이**: 001의 SC-003은 전 구간 재현성을, 002의 SC-003은 **확정 구간**
  재현성을 뜻한다. 같은 번호지만 002가 범위를 좁힌 것이다.
- **새로고침 독립성의 전제**: FR-036a는 "수집은 어제까지, 새로고침은 오늘만"이라 구간이 겹치지
  않는다는 전제에 선다. 수집 범위를 오늘까지 확장하면 이 전제가 깨지므로 그때 동시성 설계를
  다시 검토해야 한다.
- **잠금 회수**: 프로세스가 비정상 종료해 잠금이 남는 경우에 대비한 회수 기준을 둔다.
  새로고침은 수 초 내에 끝나므로 대량 수집보다 짧게 잡는다.
- **기간 프리셋 구성**: 1개월, 6개월, 1년, 5년, 10년, 전체를 제공한다. 일 단위 데이터에서
  하루·일주일 구간은 표시할 점이 너무 적어 추이로서 의미가 없으므로 제외했다.
- **"전체"의 의미**: 해당 통화의 실제 최초 제공일부터 최근 고시일까지다. 통화마다 다르다
  (USD 1964, JPY 1977, EUR 1994).
- **표와 차트의 관계**: 상세 표는 차트 기간과 독립적으로 최근 고시일 기준 일정 개수를 보여주며,
  사용자가 더 과거를 이어서 볼 수 있다. 차트 기간 전체를 표로 펼치면 30년치가 한 번에 쏟아진다.
- **표의 초기 표시 개수**: 최근 30개 고시일.
- **내려받기 형식**: 쉼표로 구분된 표 형식(CSV). 별도 도구에서 바로 열 수 있고 수치를 문자열로
  보존할 수 있다.
- **내려받기 범위**: 화면의 표에 현재 표시된 행을 대상으로 한다.
- **새로고침 조작**: 사용자가 실행하는 수동 조작만 제공하고 자동 주기 갱신은 두지 않는다
  (헌법 원칙 IX의 YAGNI). 자동 갱신은 호출 한도를 지속적으로 소비하므로 필요가 확인된 뒤에 다룬다.
- **선택 날짜의 초기값**: 화면 진입 시 가장 최근 고시일로 둔다.
- **고시 없는 날의 선택**: 001의 규칙을 따라 "고시 없음"을 주 결과로 제시하고 직전 영업일의
  값을 구분된 참고 정보로 함께 보여준다. 표에는 강조할 행이 없다.
- **수집 진행 알림**: 셸 상단에 진행 중임을 나타내는 표시를 두고, 자세한 내용은 별도 화면에서
  확인한다.
- **미구현 자산군 메뉴**: 선택할 수 없는 상태로 두고 준비 중임을 함께 표시한다.
- **대시보드·투자 비교 메뉴**: 이번 범위에서는 미구현 항목과 동일하게 취급한다.
- **동시 사용자**: 개인 사용 규모를 전제한다.

## Dependencies

- 기능 001의 수집·저장 계층과 조회 기능. 이번 기능은 그 위에 세워진다.
- 한국은행 ECOS의 가용성과 호출 한도. 오늘 값 새로고침이 한도를 추가로 소비한다. 실측으로
  확인된 것은 하루 150회 이상이라는 하한뿐이다(001 research R1).
- 헌법 v5.0.0 원칙 V의 확정/잠정 규범. 오늘 값 취급이 이 규범에 종속된다.

## Out of Scope

- 외환 외 자산군의 실제 기능(내비게이션 진입점만 둔다)
- 대시보드와 투자 비교 화면의 내용
- 복수 통화 동시 차트 비교
- 시점별 스프레드 이력 관리 — 과거 특정 시점에 실제로 적용됐던 스프레드는 알 수 없다. 알 수
  없는 값을 저장 구조로 만들면 근거 없는 숫자에 신뢰가 생긴다.
- 오늘 값의 장중 변동 이력 보존(확정 전환 추적은 원본 응답 기록으로 갈음한다)
- 수집 방식과 저장 구조의 근본적 변경
- 차트 이미지 내보내기, 주석·드로잉 도구
- 사용자 인증 및 사용자별 설정 분리
