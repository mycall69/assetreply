# Data Model: 외환 분석 화면 통합과 전역 내비게이션 셸

**Feature**: 002-fx-analysis-workspace | **Date**: 2026-08-30

001의 7개 테이블을 그대로 쓴다. 이 문서는 **변경분만** 다룬다. 변경되지 않은 테이블의 정의는
[001 data-model.md](../001-fx-rate-history/data-model.md)를 참조한다.

스키마 변경은 Alembic 리비전으로만 관리한다(헌법 v5.0.0 DB 운영 규약). 수동 DDL은 금지한다.

## 1. `fx_rate` — 확정/잠정 구분 추가

### 추가 컬럼

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `is_provisional` | `BOOLEAN` | NOT NULL, DEFAULT `FALSE` | 출처가 아직 확정하지 않은 값인지 (헌법 v5.0.0 원칙 V) |

기존 컬럼과 기본 키 `(currency_code, quote_date)`는 변경하지 않는다. 멱등 upsert의 근거가
그대로 유지된다.

### 마이그레이션

기존 행은 전부 확정값이므로 `DEFAULT FALSE`로 채운다. 백필이나 데이터 이동이 필요 없다.

### 상태 전이

```text
       (없음)
          │  오늘 새로고침 (ingestion/today.py)
          ▼
   is_provisional = TRUE      ←──┐ 같은 날 재요청 시 값만 갱신
          │                      │ (updated_at 변경, 상태 유지)
          │  날짜가 지난 뒤 증분 수집이 그 날짜를 다시 받아옴
          ▼
   is_provisional = FALSE  (확정. 이후 값이 바뀌지 않는다)
```

**전이 규칙**

- 잠정 → 확정은 **값을 다시 받아왔을 때만** 일어난다. 상태만 뒤집는 경로를 만들지 않는다
  (FR-037a, research R2-3).
- 확정 → 잠정 역방향 전이는 없다. 확정된 값이 다시 불확실해지지 않는다(FR-042).
- 출처가 확정값을 정정하면 001의 FR-003a 규칙대로 값과 `updated_at`을 갱신하되
  `is_provisional`은 `FALSE`를 유지한다. 정정은 잠정과 다른 개념이다.

### 검증 규칙 (001에 추가)

- `is_provisional = TRUE`인 행은 통화당 최대 1개이며 `quote_date`는 오늘이어야 한다
  (**FR-037c** — 이 불변식의 정본은 명세다. 여기서는 저장 관점의 서술만 둔다).
  과거 날짜에 잠정 행이 남아 있다면 증분 수집이 그 날짜를 건너뛰었다는 뜻이므로 결함이다.
- `quote_date` 상한 제약이 001의 "오늘 미만"에서 **"오늘 이하"**로 완화된다. 오늘 행은
  `is_provisional = TRUE`일 때만 허용된다.

### 조회 규약

- 확정 구간 조회는 `is_provisional = FALSE`만 대상으로 한다. 이것이 SC-003(재현성 100%)의
  구현 근거다.
- 요약·차트·표는 잠정 행을 포함하되 상태를 함께 반환해 화면이 구분할 수 있게 한다
  (FR-014, FR-017a, FR-025).
- **잠정 잔존 조회**: `is_provisional = TRUE AND quote_date < 오늘`인 행을 통화별로 묶어
  가장 오래된 날짜를 구한다(FR-043a, research R2-11). 오늘 날짜는 제외한다 — 정상
  상태다(FR-043b). 이 조회가 의미를 갖는 근거는 **앞의 검증 규칙**(FR-037c)이 과거 날짜의
  잠정 저장을 막는 데 있다. 막지 않으면 잔존의 원인이 둘로 갈라져 신호가 무의미해진다.

## 2. `fx_coverage` — 잠정 반영 금지 (스키마 변경 없음)

컬럼은 그대로다. **규칙만 바뀐다.**

- `covered_through`는 확정 수집만 반영한다. 오늘 잠정 행을 저장해도 전진하지 않는다.
- 따라서 `covered_through`는 항상 어제 이하다.

**왜 중요한가**: 001의 재개 로직이 `covered_through + 1`부터 다시 받는다. 잠정 저장이
커버리지를 오늘까지 밀면 다음 증분 수집이 오늘을 건너뛰고, 잠정값이 영원히 확정되지 않는다.
이 규칙이 R2-3의 확정 전환 경로를 성립시키는 전제다(FR-037b, research R2-2).

001의 영업일 판정(고시 없는 날 = 커버리지 안인데 값이 없는 날)도 이 규칙 덕분에 오늘에 대해
잘못된 답을 내지 않는다. 오늘은 커버리지 밖이므로 "고시 없는 날"로 판정되지 않는다.

## 3. `fx_collection_lock` — 잠금 범위 추가

### 변경

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `scope` | `VARCHAR(20)` | PK (신규) | 잠금 종류. `collection` 또는 `today_refresh` |
| `currency_code` | `CHAR(3)` | PK (기존) | |

**키 변경**: `PRIMARY KEY (currency_code)` → `PRIMARY KEY (scope, currency_code)`

나머지 컬럼(`job_id`, `acquired_at`, `heartbeat_at`)은 유지한다.

### 마이그레이션

기존 행에 `scope = 'collection'`을 채운 뒤 기본 키를 재정의한다. 잠금은 실행 중에만 존재하는
휘발성 데이터이므로, 마이그레이션은 서비스 정지 상태에서 수행하거나 기존 행을 비우고 진행해도
무방하다.

### 왜 컬럼 하나로 해결하는가

FR-036a는 "새로고침이 수집 잠금과 독립"을, FR-036b는 "새로고침끼리는 하나만"을 요구한다.
현재 기본 키가 `currency_code` 하나라 새로고침이 같은 테이블을 쓰면 수집과 충돌한다.

범위를 키에 넣으면 두 요구가 동시에 만족되고, 001이 세운 메커니즘(기본 키 INSERT 충돌 =
진행 중, 하트비트로 스테일 회수)을 그대로 재사용한다. 표준 SQL만 쓰므로 DB 이식성 규약도
유지된다(research R2-8).

### 스테일 회수

| 범위 | 만료 기준 | 근거 |
|------|-----------|------|
| `collection` | 001의 기존 값 | 청크 커밋마다 하트비트가 갱신된다 |
| `today_refresh` | 더 짧은 값 (설정값) | 단일 호출이라 수 초 내 끝난다. 길게 잡으면 프로세스가 죽었을 때 새로고침이 오래 막힌다 |

두 값 모두 `config/settings.py`에 설정으로 선언한다(헌법 원칙 II).

## 4. `fx_spread` — 변경 없음

기본값 복원(FR-031)은 스키마를 바꾸지 않는다. 001의 시드 리비전에 있는 값을 **단일 출처**로
삼아 그 값으로 되돌린다.

| 통화 | `cash_buy` | `cash_sell` | `remit_send` | `remit_receive` |
|------|-----------|------------|-------------|----------------|
| USD | 0.001800 | 0.001800 | 0.000500 | 0.000500 |
| JPY | 0.002000 | 0.002000 | 0.000600 | 0.000600 |
| EUR | 0.002000 | 0.002000 | 0.000600 | 0.000600 |

**설계 주의**: 기본값을 애플리케이션 코드에 다시 적지 않는다. 시드 리비전과 복원 로직이 각각
값을 갖고 있으면 언젠가 어긋난다. 기본값을 한 곳에 선언하고 시드와 복원이 함께 참조한다.

## 5. 파생 환율 — 저장하지 않음 (001과 동일)

표의 4종 파생 환율은 조회 시점에 `simulation/spread_calc.py`로 산출한다. 저장하지 않는
이유는 001과 같다 — 스프레드가 바뀌면 저장된 값이 즉시 무효가 된다.

이번 기능에서 달라지는 것은 **산출 주체가 서버로 고정**된다는 점이다. 브라우저에는 `Decimal`이
없어 클라이언트 계산이 곧 원칙 VI 위반이 된다(research R2-5).

잠정 매매기준율로 산출한 파생 환율은 결과에도 잠정임이 따라붙어야 한다(FR-041).

## 6. 화면 선택 상태 — 저장하지 않음

선택 통화·선택 날짜·차트 기간은 브라우저 세션 안에서만 유지한다. 서버에 저장하지 않는다.

사용자 계정 개념이 없고(001 Out of Scope), 이 상태는 재현성 요구 대상이 아니다. 화면을
새로 열면 기본값(가장 최근 고시일, 기본 통화, 기본 기간)에서 시작한다.
