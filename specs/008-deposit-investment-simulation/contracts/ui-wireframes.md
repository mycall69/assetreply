# UI Wireframes: 예금 투자 시뮬레이션

**Feature**: `008-deposit-investment-simulation` | 근거: [rest-api.md](./rest-api.md), [research.md](../research.md) R8-10

화면은 주식(`/stocks`)·가상자산(`/crypto`)을 본뜬다. 아래는 **그 둘과 다른 곳**만 그린다 — 나머지(시작일 입력, 수집 안내의 진행 줄,
성과 보드의 칸, 이력 비교)는 005~007과 같다. 금액은 통화 기호를 숫자 앞에 둔다(007 FR-042a), 차트 축은 천 단위 쉼표(007 FR-043a·FR-046a).

---

## D1. 메뉴와 화면 (FR-001~FR-005)

```
 AssetReplay              │ 예금 투자 시뮬레이션
 ─────────────            │ 1년 만기 정기예금에 가입하고 만기마다 세후 이자를 더해 재예치한 성과
  대시보드   준비중        │
  외환                    │ ┌───────────────────────────────────────────────────────────────────┐
  가상자산                │ │ 투자처  (●) 시중은행   ( ) 저축은행   ( ) 신협   ( ) 상호금융   ( ) 새마을금고 │
  주식                    │ │         예금은행 정기예금(1년) 평균 — 일반·특수은행 포함 · 2012-01부터     │
▶ 예금                    │ │ 시작일 « ‹ [2020-01-01] › »   투자 원금 [ 10,000,000 ] 원   [ 시뮬레이션 ] │
  부동산     준비중        │ └───────────────────────────────────────────────────────────────────┘
  투자 비교  준비중        │
  설정                    │  출처: 한국은행 경제통계시스템(ECOS) · 신규취급액 기준 가중평균 금리
```

- 메뉴 순서는 그대로(외환 → 가상자산 → 주식 → **예금** → 부동산), 예금의 "준비중"이 사라진다(FR-001)
- 투자처는 **라디오 버튼 다섯**, 기본 시중은행(FR-003). 고른 투자처 아래 한 줄: 통계 설명과 시작 가능 달(받아 두었으면 — `GET
  /api/deposit/institutions`의 `firstMonth`, 모르면 줄의 앞부분만). 이름 다섯은 고정이라 화면이 목록을 받기 전에도 그린다
  (`depositStore.INSTITUTION_NAMES`). 설명·시작 가능 달만 `GET /api/deposit/institutions`가 준다 — 목록을 받지 못해도 고르고 실행할 수
  있다. 이름을 바꿀 때는 서버(`deposit_simulation.INSTITUTIONS`)와 함께 바꾼다
- 원금은 **원화만** — 통화 칸이 없고 단위 "원"을 글자로 둔다(FR-004). 3자리 쉼표(006과 같다)
- 재투자(재예치) 선택 칸이 **없다** — 항상 재예치한다(FR-002)
- 화면 아래 출처 줄(research R8-2, 헌법 원칙 II)

## D2. 투자처를 바꿀 때

- 다른 투자처를 고르면 결과를 지운다(이전 투자처의 결과를 새 투자처 이름 아래 남기지 않는다). 실행은 버튼으로 한다 — 주식에서 종목을
  바꿀 때와 같다
- 시작일이 그 투자처의 시작 가능 달보다 이르면 실행 뒤 409 안내와 "2012-01-01로 옮기기" 수단(FR-006, 006과 같은 안내)

## D3. 성과 보드 (FR-035)

```
┌──────────────────────┬──────────────────────┬──────────────────────┐
│ 투자 원금             │ 투자 수익             │ 수익률                │
│ ₩10,000,000          │ ₩1,557,207           │ +15.57%              │
├──────────────────────┴──────────────────────┴──────────────────────┤
│ 2026-10-04 기준 · 시중은행 · 세율 15.4% · 지금 회차 2026-01-15 가입 · 2.84% · 만기 2027-01-15 │
└────────────────────────────────────────────────────────────────────┘
```

잠정일 때 — 보드 아래 줄(`role="status"`):

```
 ⓘ 잠정 — 2026-09-15 가입(재예치) 금리가 아직 발표되지 않아 2026-08 금리(3.39%)로 계산했습니다. 금리가 발표되면 값이 바뀝니다.
```

결측으로 멈췄을 때 — 보드 아래 줄(`role="status"`, 007의 끊김 안내와 같은 자리):

```
 ⚠ 2024-03 금리 통계가 비어 있어 2024-03-15 만기에서 계산을 멈췄습니다. 그날까지의 결과입니다.
```

- `PerformanceBoard`를 그대로 쓴다 — 기준 줄의 덧붙임(`notes`)에 투자처·세율·지금 회차(FR-035)
- 잠정 줄은 **잠정 시작일, 대신 쓴 금리의 달과 값, "발표되면 값이 바뀐다"**를 모두 담는다(SC-005)
- 오늘 금리 확인이 실패했으면(`summary.recheckFailed`) 같은 자리에 "오늘 금리 확인에 실패했습니다(사유) — 받아 둔 금리로 계산했습니다.
  내일 다시 확인합니다" 줄을 더한다(FR-016). 종류가 인증이면 끝에 "인증키 설정을 확인하세요.", 형식이면 "출처의 응답 형식이 바뀌었습니다 —
  어댑터를 고쳐야 합니다."를 붙인다 — 한도·연결은 기다리면 되므로 붙이지 않는다(FR-016a, 반복 #2)
- 줄의 순서는 잠정 → 멈춤 → 확인 실패다. 잠정과 멈춤은 함께 나오지 않는다(FR-035)


- 적용 금리 칸: 금리와 그 금리의 달. 잠정이면 "(26-08 대신)"처럼 대신 쓴 달을 밝힌다(FR-033)
- 월 행의 이자·세금·세후 이자는 **경과분**, 만기 행은 만기 이자(FR-032). 경과분이라는 사실을 머리글 도움말(`title`)로 밝힌다
- 최신순, 한 번에 모두(행이 적다 — contracts). 열 폭은 내용에 맞추고 브라우저 창 1440px에서 가로 스크롤이 없다(FR-034)

## D5. 성과 추이 차트 (FR-036)

```
 잔고(KRW) 11,600,000 ┤                                ╭──┄┄┄   ├ 16.00   범례: ─ 잔고 (KRW)  ╌ 수익률 (%)  ┄ 잠정(2026-09-15부터)
           10,000,000 ┤──╮─────╭─────╭────────╭─────╯         ├ 0.00
```

- `PerformanceChart`를 그대로 쓰고 **선택 속성 `provisionalFrom`**을 더한다 — 그 날짜부터 같은 두 선을 **연한 색**으로 이어 그리고 범례에
  "잠정(날짜부터)"을 쓴다. 주식·가상자산은 `null`이라 그대로다(research R8-10)
- 점은 표의 행 날짜 + 계산 끝(contracts). 결측으로 멈췄으면 그 만기일에서 끝난다

## D7. 설정 — 예금 이자 소득세율 (FR-030, FR-031)

```
 주식
   매매 수수료        [ 0.015 ] %
   배당 소득세 (국내) [ 15.4  ] %
   배당 소득세 (해외) [ 15    ] %
 가상자산
   거래 수수료        [ 0.1   ] %
 예금
   이자 소득세        [ 15.4  ] %   (기본값 — 소득세 14% + 지방소득세 1.4%)
                                    [ 저장 ]
```

- 주식·가상자산 설정과 **따로** 저장한다. 0 이상 100 미만이 아니거나 소수 4자리를 넘으면 저장하지 않고 사유를 보인다(FR-030, 반복 #2)
- 기본값과 다르면 "기본값으로" 수단(006과 같다)

## D8. 수집 안내와 실패 (FR-011, FR-016)

```
 ⟳ 시중은행의 금리를 받고 있습니다 | 0 / 82개월
 ⚠ 금리 출처 인증에 실패했습니다. 이미 받은 구간으로 계산할 수 있으면 계속 보입니다 — 인증키 설정을 확인하세요.
```

| 종류 | 문구 | 할 일 |
|------|------|-------|
| `auth` | 금리 출처 인증에 실패했습니다. — 인증키 설정을 확인하세요. | 설정 수정 |
| `rate_limited` | 금리 출처의 호출 한도를 넘었습니다. 잠시 뒤 다시 실행하세요. | 기다린다 |
| `format` | 금리 출처의 응답 형식이 바뀌었습니다. — 어댑터를 고쳐야 합니다. | 코드 수정 |
| `network` | 금리 출처에 연결하지 못했습니다. 다시 실행하면 이어서 받습니다. | 다시 실행 |

- **받아 둔 투자처의 수집이 실패하면 화면이 곧바로 한 번 다시 요청한다**(FR-016a, 반복 2026-10-04) — 받아 둔 투자처는 투자처 목록의
  `firstMonth`가 있는 것이다. 서버는 받아 둔 금리로 계산해 200 + `recheckFailed`를 주므로 실패 문구 대신 결과와 보드 아래 확인 실패 줄(D3)이
  남는다. 받은 적 없는 투자처는 다시 요청하지 않는다(같은 실패가 되풀이된다) — 위 실패 문구만 보인다. 다시 요청은 한 실행에 한 번이다
- 진행 줄은 006 `CollectingNotice`와 같다(받은 달 / 받을 달 — 단위 "개월")
- 받을 달은 그 실행에 필요한 구간(시작 달 ~ 이번 달)이다 — 처음 받는 투자처도 처음부터 안다(예: 2020-01-15 시작이면 82개월). 요청이
  하나라 0에서 곧바로 결과로 바뀐다. 미발표 달은 받지 못한 채 끝나며 결과의 잠정 표시로 드러난다(data-model 4절)

## 접근성

- 라디오 버튼은 `fieldset`·`legend`("투자처")로 묶는다. 각 항목의 설명 줄은 `aria-describedby`로 잇는다
- 보드 아래 잠정·멈춤 줄은 알림 역할(`role="status"`), 실패는 경고 역할(`role="alert"`)이다(005~007과 같다)
- 표의 구분·잠정은 글자다. 손익은 부호와 함께(`+15.57%`, `-₩…`)
- 수집 진행 막대는 `role="progressbar"`와 값·범위를 가진다(006 `CollectingNotice`)
