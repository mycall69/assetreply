# Quickstart: 예금 투자 시뮬레이션 — 검증 안내

**Feature**: `008-deposit-investment-simulation` | 근거: [contracts/rest-api.md](./contracts/rest-api.md),
[contracts/ui-wireframes.md](./contracts/ui-wireframes.md), [data-model.md](./data-model.md), [research.md](./research.md)

기능이 처음부터 끝까지 동작함을 보이는 시나리오다. 구현 코드는 tasks와 구현 단계의 몫이다.

## 준비

```bash
cd backend && .venv/bin/python -m alembic upgrade head      # 예금 테이블 6개 (data-model)
./be-start.sh && ./fe-start.sh                                # 백엔드 8080(단일 워커), 프론트엔드 3030
```

- `.env`의 `ECOS_API_KEY`는 001부터 있다 — 예금 금리도 같은 키를 쓴다. 키 값을 출력하거나 셸 인자로 넘기지 않는다
- **개발 서버를 띄운 채 통합 테스트를 돌리지 않는다**(CLAUDE.md)

## 자동 검사

```bash
cd backend && .venv/bin/python -m pytest -q --cov=src        # 네트워크 없이 통과(헌법 원칙 III), 커버리지 80%+
cd backend && .venv/bin/python -m mypy src && .venv/bin/python -m ruff check --no-cache src tests
cd frontend && npm test && npx tsc --noEmit && npx eslint .
```

계약 테스트는 ECOS의 **실제 응답을 저장한 픽스처**로 한다 — 두 통계표의 항목 목록(`121Y002`·`121Y004`), 다섯 투자처의 전체 시계열,
미발표 구간(`INFO-200`), 인증 실패(`INFO-100`), 한도 초과(`INFO-300`). 픽스처에 인증키가 없는지 확인한다(응답 본문에는 키가 없다 — 요청
URL을 저장하지 않는다).
