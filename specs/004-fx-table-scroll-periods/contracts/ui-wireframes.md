# Contract: UI 와이어프레임 — 004

**Feature**: 004-fx-table-scroll-periods | **Date**: 2026-09-27

002가 만든 일자별 환율 상세 표를 **대체하지 않고 확장한다.** 열 구성·서식·강조 규칙은
002의 것을 그대로 쓴다(FR-016).

와이어프레임은 **배치와 정보의 계층**을 정한다. 색·여백·타이포그래피는 구현에서 결정한다.

---

## W1. 표 머리 — 기간 단위 선택기

```
┌──────────────────────────────────────────────────────────────────────┐
│  일자별 환율 상세                                                     │
│                                                                      │
│  ┌─────┬─────┬─────┐                              ┌──────────────┐  │
│  │ 일  │ 주  │ 월  │                              │  ↓ 내려받기  │  │
│  └━━━━━┴─────┴─────┘                              └──────────────┘  │
│                                                                      │
│  날짜          매매기준율   현금 살 때  현금 팔 때  송금 보낼  송금 받을│
│  ──────────────────────────────────────────────────────────────────  │
```

**배치 규칙**

- 선택기는 표 **왼쪽 위**, 내려받기는 오른쪽 위다. 왼쪽이 "무엇을 볼지", 오른쪽이 "가져갈지"다.
- `일`이 기본 선택이며 002의 `CurrencyTabs`와 **같은 분절 컨트롤 형태**를 쓴다 — 컨테이너가
  회색, 활성 항목이 흰색. 통화 선택기와 같은 모양이라 사용자가 한 번만 익히면 된다.
- 002의 `더 보기` 버튼은 **사라진다**(FR-001).

---

## W2. 행 표시 — 세 가지가 겹칠 수 있다

한 행에 붙을 수 있는 표시가 셋이고, **서로 구별되어야 한다**(FR-015b).

```
  날짜               매매기준율   현금 살 때  ...
  ──────────────────────────────────────────────
  2026-09-23  ⏳ 📅  1,360.00    1,362.45   ...   ← 진행 중 + 기준일 옮김
  2026-09-18         1,383.80    1,386.29   ...   ← 금요일, 정상
  2026-09-11         1,338.20    1,340.61   ...
  2026-07-16     📅  1,401.20    1,403.72   ...   ← 7-17(금) 결측 → 7-16
  ...
```

| 표시 | 뜻 | 조건 |
|------|-----|------|
| `📅` | **기준일이 옮겨졌다** | `shiftedFrom`이 있을 때 (FR-013) |
| `⏳` | **구간이 진행 중이다** | `isOngoing`이 참일 때 (FR-015a) |
| `⚠ 잠정값` | 값이 확정되지 않았다 | 002 FR-025 그대로 |

**셋을 하나의 아이콘으로 합치지 않는다.** 합치면 사용자가 이유를 알 수 없어 표시가
무의미해진다. 각각 다른 기호를 쓰고, 마우스를 올리거나 보조 기술로 읽을 때 설명이 나온다.

**옮겨진 행은 원래 기준일을 함께 알린다.**

```
  2026-07-16  📅         ← "7월 17일(금)에 고시가 없어 7월 16일 값입니다"
```

이 설명이 FR-013의 요구다. 없으면 사용자는 1,401.20을 **7월 17일 값으로 믿는다.** 값은
정확한데 무엇의 값인지를 잘못 알게 된다.

**옮겨지지 않은 행에는 표시가 없다**(FR-014). 모든 행에 늘 표시가 있으면 구별의 의미가
사라진다.

## W3. 이어 보기 — 스크롤 끝

```
  ...
  2026-08-12         1,415.00    1,417.55   ...
  ──────────────────────────────────────────────
              ⟳ 불러오는 중…                        ← 받는 동안
```

```
  ...
  1964-05-04         130.00      130.23     ...
  ──────────────────────────────────────────────
         1964-05-04까지 모두 표시했습니다              ← 끝에 도달 (FR-002)
```

```
  ...
  2020-03-15         1,219.30    1,221.49   ...
  ──────────────────────────────────────────────
     불러오지 못했습니다  [ 다시 시도 ]                ← 실패 (FR-004)
```

**끝에 도달했음을 반드시 알린다**(FR-002). 알리지 않으면 사용자는 아직 받는 중이라고 여겨
기다린다 — **아무 일도 일어나지 않는데 기다리는** 상태가 된다.

**실패해도 이미 표시된 행은 유지한다**(FR-004). 조용히 멈추면 사용자는 데이터가 거기서
끝난 것으로 오해한다. 다시 시도할 수단을 함께 둔다.

**새 행은 목록 끝에 덧붙인다**(FR-003). 전체를 다시 그리면 보던 위치가 처음으로 튄다.

## W4. 선택 날짜 강조 — 구간 기준

일 단위에서 2026-09-16을 고른 뒤 주 단위로 바꾼 경우다.

```
  날짜               매매기준율   ...
  ──────────────────────────────────────────────
  2026-09-23  ⏳ 📅  1,360.00    ...
▶ 2026-09-18         1,383.80    ...   ← 강조 (09-16이 속한 주)
  2026-09-11         1,338.20    ...
  ──────────────────────────────────────────────
  선택한 2026-09-16이 속한 주의 값입니다
```

**강조된 행의 날짜와 선택 날짜가 다르다는 사실을 알린다**(FR-019a). 알리지 않으면 사용자는
자신이 고른 날짜가 09-18로 바뀌었다고 오해한다.

**선택 날짜 자체는 바뀌지 않는다**(FR-019b). 일 단위로 돌아오면 09-16이 그대로 강조된다.

### 속한 구간에 행이 없을 때

```
  ──────────────────────────────────────────────
  선택한 1990-01-15이 속한 주에는 고시가 없습니다
```

강조가 그냥 사라지면 사용자는 선택이 풀린 것으로 오해한다(FR-020).

## W5. 단위 전환 — 즉시 비운다

```
  [ 일 ] → [ 주 ] 클릭

  ┌──────────────────────────────────────────┐
  │  ⟳ 불러오는 중…                           │   ← 이전 단위 행이 남지 않는다
  └──────────────────────────────────────────┘
```

**전환 즉시 비운다**(FR-010). 새 단위의 응답이 도착할 때까지 이전 단위의 행이 남으면
사용자가 지금 보는 행이 어느 단위의 것인지 알 수 없다.

**뒤늦게 도착한 이전 단위의 응답은 버린다**(FR-011). 002·003이 쓴 것과 같은 방식이다 —
응답에 실린 `period`를 현재 선택과 대조해 거른다.

스크롤 위치도 처음으로 돌아간다.

## W6. 과거 날짜 선택 — 표를 새로 받는다

스크롤로 2020년까지 쌓은 상태에서 1990-01-15를 고른 경우다.

```
  ┌──────────────────────────────────────────┐
  │  ⟳ 1990-01-15 주변을 불러오는 중…          │
  └──────────────────────────────────────────┘

  → 쌓아 둔 2020~2026 행은 버려진다 (FR-005a)
  → 스크롤 위치가 처음으로 돌아간다 (FR-005b)
```

이어 붙이면 30년치를 한꺼번에 받게 되어 응답이 커진다. 002 FR-022a의 "그 날짜가 포함되도록
표를 다시 받는다"를 그대로 잇는다.

## W7. 내려받기

파일에는 **화면과 같은 단위**의 행이 담긴다(FR-016a). 주 단위로 보다가 내려받으면 주별
행이 나온다.

| 열 | 비고 |
|----|------|
| 기존 열 | 002가 정한 그대로 |
| 기간 단위 | 파일만 봐도 어느 단위인지 알아야 한다 |
| 원래 기준일 | 옮겨졌을 때만 값이 있다 |
| 진행 중 | 참/거짓 |

**표시가 파일에서 빠지면 화면에서 막은 오해가 파일에서 되살아난다**(FR-016b). 파일만 본
사람은 2026-07-16을 그냥 7월 데이터로 읽지, 7월 17일의 대체값인 줄 모른다.

## 접근성

- 기간 단위 선택기는 키보드로 이동·선택할 수 있어야 하고, 현재 선택이 보조 기술에 읽혀야
  한다. 002의 `CurrencyTabs`가 `role="tablist"`로 이미 충족하는 형태를 따른다.
- `📅`·`⏳`는 장식이 아니라 의미를 지니므로 **기호만으로 전달하지 않는다.** 각각 텍스트
  대체를 두고, 색만으로 구별하지 않는다.
- 이어 보기의 상태(불러오는 중·끝·실패)는 알림 역할이므로 화면에 나타날 때 스크린 리더가
  알린다.
- 강조된 행은 색만이 아니라 다른 수단으로도 구별되어야 한다(002가 세운 규칙).
